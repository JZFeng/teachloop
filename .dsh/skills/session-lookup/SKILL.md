# Session Lookup（会话检索）

一句话：**用户报关键词，我给标题**——不给总结、不替他打开，只让他能在左侧列表里一键定位。

## 何时使用

- 前缀 `会话：` / `session：`（全角半角冒号都算），后面是任何形式的描述。
- 「上次那个聊 SMTP 的会话是哪一次」「我记不得哪个 session 讨论过平板适配了」。
- **不适用**：用户要的是内容而不是位置（直接查代码/文档）；会话就是当前这条（`session-7c…` 这类当前 id 不必检索，除非用户明确要别的）。

## 执行四步

1. **解析**：取前缀后的描述原样保留，别改写用户的说法。
2. **组词**：从描述里抽 2–4 个词，中英各留一版（本项目常见对照：平板↔tablet/iPad、部署↔deploy、注册↔register/smtp、复习↔review）。专有名词（文件名、页面路径、提交号）直接用。
3. **检索**：
   ```bash
   python3 scripts/find-session.py 平板 tablet --limit 6
   ```
   - 第一次跑会建索引（本机 ~150 个会话，约 3–5 秒），之后单次 < 1s；缓存在 `.dsh/tmp/session-index/`（gitignored）。
   - 关键词都不命中时，去掉 `--all`（默认就是任一命中）并换成更短的词；仍无命中再用 `--fast` 只搜标题与首条消息，确认是不是词压根没出现过。
   - 用户只记得大致方向时，`--limit 10` 多给几个候选。
   - **别把「会话」「session」当关键词**：脚本会按 78/150 的占比把它们判成通用词并自动忽略（`--keep-common` 可关掉），但更省事的做法是直接挑内容词。
   - 排序权重：你的原话 3、助手回复 1、标题/首条 6。所以片段优先贴**用户自己说的话**，助手回复只做补充。
4. **定稿回复**（BLUF）：第一行就是标题，后面的字段用于让他确认「就是这个」。

## 回复模板

```
**标题：「登录页布局偏下问题」**（在左侧列表里按这个标题找）

- 时间：2026-10-27 23:23 → 2026-10-28 08:47（最近活动）
- 工作区：teachloop　会话 `session-7025a606-bb3b-4f20-8a66-0d0f955ac409`
- 状态：**已归档**——先把列表筛选切到「全部对话（显示已归档）」再找
- 为什么是它：你当时说「我们的其它屏幕怎么适配？至少应该适配一下 tablet…」（命中 平板×13、tablet×5）
```

- **标题必须独占一行、可整行复制**，不要塞进句子里（用户要拿它去列表里搜）。
- 有 2 个以上同为高分候选时，列 2–3 个并写清差别（时间、首条消息、命中词），让用户自己认。
- 归档状态每次都要读实时值（`workspace.json`），不能凭上一轮记忆说「没归档」。
- 只返回位置，不返回长摘要。用户问了内容才展开，且说明「以下是摘要，不是原文」。

## 纪律

- **不编标题**：标题只来自 `session_projcache`；取不到就写「（无标题）」并用首条消息当识别锚点。
- **不擅自切换/打开会话**：我没有「切过去」的能力，只有用户自己能点；不要写「已为你打开」。
- **不把归档会话说成能直接看到**：默认列表隐藏归档会话，漏掉这句用户会以为我找错了。
- **命中靠片段自证**：贴 1–2 条原始片段（用户自己的话优先），不要只给命中次数。
- **样板文本不进索引**：`agent-instructions` / `runtime-context` / `skill-catalog` / `time-context` 这几类 user/message 是每条会话都注水的注入内容，脚本已按 `source.kind` 排除；不要为了「搜得到」把它们加回去，否则任何词都会命中所有会话。
- **本机 GUI 的正文搜索不可靠**：Web 部署把 `session-query-sqlite` 配成 `path: ':memory:'`、`openAt: never`，全文搜索是关的；所以别教用户「在搜索框里输入平板」——按标题找、按归档筛选才是稳的。

## 实现锚点

| 东西 | 位置 |
|---|---|
| 检索脚本 | `scripts/find-session.py`（`--limit/--all/--fast/--json/--refresh`） |
| 会话正文 | `$DSH_HOME/sessions/<workspace>/session-<id>/session.v4.jsonl.zstd` |
| 标题与首条消息 | `$DSH_HOME/storages/session_projcache/sessions/<id>.json` |
| 归档 / 置顶 | `$DSH_HOME/storages/workspace.json` 的 `global.archivedSessionIds` / `pinnedSessionIds` |
| 索引缓存 | `.dsh/tmp/session-index/`（按 size+mtime 增量，可整目录删） |
