# 项目宪法 — AI 批量批改作业系统

本文件是**不可协商的原则**。`specs/` 下的规格、方案、任务与所有代码都不得违背。
任何违宪的改动必须先修改本文件并说明理由。

- 版本：**2.1**
- 日期：2026-10-19
- 适用范围：`specs/002-v2-platform/` 及此后的全部实现代码

> 版本 2.0 的改动由用户 review 驱动：公网部署、取消 OCR、客观题判分、中英双语、
> 学生可见同班概览、可观测性。`.docs/archive/001-batch-grading-web/` 作为 v1 历史保留。

---

## 第一条 — 教师拥有最终决定权

AI 的输出**永远是草稿**，不是成绩。

- 任何分数在学生看到之前，必须经过教师的显式动作（批准 / 小改 / 大改 / 驳回）。
- 系统不得存在"跳过教师直接发布"的默认路径。
- UI 上任何位置都不得把 AI 草稿表述为"最终成绩"。
- 本条不因自动化程度提高而放宽：定时派发只负责"送进批改"，不负责"发布"。

## 第二条 — 一切可审计

从提交到发布，每一步都必须可回溯。

- 必须记录：谁、何时、对哪一份、做了什么、改前是什么、改后是什么。
- 至少覆盖：提交、发起新 attempt、派发批改、AI 判分完成、教师决定、内容修改、发布、撤回、导出。
- 审计记录**只追加，不修改，不提供删除接口**。
- 学生看到的反馈必须能追溯到某一版已批准的草稿。

## 第三条 — Rubric 优先，且以数据形式存在

- 评分标准存在数据库里，不写在代码里，也不只存在提示词里。
- 作业由若干**部分**组成，每个部分声明自己的判分方式：`objective`（代码判分）或
  `subjective`（AI 判分）。
- 客观部分的标准答案、可接受写法、匹配规则、每题分值都是数据，教师可增删改。
- 篇幅口径（几段、几分钟）属于作业设置，由作业作者填写。
- 系统可以为 AI 提供**确定性证据**（词数、段数、时长），但不得用代码替教师做主观判定。

## 第四条 — 读不到 ≠ 0 分

- 解析失败、文件损坏、视频无法探测，一律标记为 `unreadable` 并**禁止给分**。
- 不得根据文件名、页数或猜测填充内容。
- 视频在未转写时不得因"没有文本"被判 0 分，必须走人工复核。
- 此类作业必须在教师界面上单独列出，且不参与平均分。

## 第五条 — 客观题由代码判，AI 不参与

- 客观题（选择题、填空题等有标准答案的题项）的判分**必须**由代码完成。
- AI 请求体**不得包含**标准答案、客观题得分或客观题作答明细。
- AI 只接收主观部分、学生正文与客观指标；客观得分在合成阶段由代码合并。
- **唯一的例外**：生成**错题解析**时，AI 可以使用该题的题干、选项与标准答案——
  不看到答案就写不出「为什么错」。但此时：
  - 不得传入学生身份、作答人是谁、或其他学生的任何数据；
  - 不得据此产出或修改任何分数；
  - 解析只作为教学材料，不参与计分。
- 判分路径与解析路径必须是两个独立的入口（`GradingEngine` 与 `ExplanationEngine`），
  不得共用一个能同时拿到答案与学生的调用。
- 词数、段数、时长、分辨率等可确定性计算的指标，同样只能由代码计算，
  模型不得自行重算。
- 同一次批改中，同一指标只能有一个来源。

## 第六条 — 可替换的边界

以下四处**必须**以接口形式隔离，实现可整体替换而不改动调用方：

1. **认证提供者**：微信扫码 / 公众号网页授权 / 管理员密码 / 本地开发替身。
2. **AI 执行引擎**：直连模型 API（生产）/ `dsh headless`（本地开发）/ 仅脚本（降级）。
3. **对象存储**：本地目录（开发）/ 阿里云 OSS（生产）/ MinIO。
4. **PDF 渲染**：文档渲染后端（当前为 WeasyPrint）。

OCR 提供者的接口定义保留，但 **v1 不实现、不启用**。

任何"写死"这些边界的方式都视为违宪。

## 第七条 — 隐私与班级隔离

- 学生可以看到**同班同学的概览**：姓名、是否提交、attempt 次数、提交时间、分数、复核状态。
- 学生**不得**获取同班他人的作业正文、附件、文件下载链接、AI 评语、教师评语。
- 越权访问一律返回 **404**，不得用 403 泄露资源是否存在。
- 跨班级数据默认不可见；教师只能看到自己所属的班级。
- 作业内容仅在批改所需的范围内传递；任何上传第三方的路径必须在文档中显式声明。
- 日志中不得记录作业正文。

## 第八条 — 技术标准

| 项 | 规定 |
| :--- | :--- |
| 后端语言 | **Java 21**（LTS） |
| 后端框架 | **Spring Boot 4.1.x**（Spring Framework 7） |
| 序列化 | **Jackson 3**（包名 `tools.jackson`）；不得引入 Jackson 2 |
| 数据库 | PostgreSQL 16+，迁移用 **Flyway**，**按模块分目录**（§plan 3.3），禁止手改线上表结构 |
| 队列 | **不引入独立消息队列**：工作项就是数据库中的提交行，用条件更新领取；定时任务用 Spring `@Scheduled` + ShedLock |
| 实时推送 | **不用 SSE**：前端按 2 秒轮询进度接口；进度只从数据库聚合，不依赖进程内状态 |
| 对象存储 | 阿里云 OSS（生产）/ 本地目录（开发），统一走 `StorageBackend` |
| 前端 | React + TypeScript，构建用 Vite |
| 时间 | 一律存 UTC，展示用用户时区；**必须注入 `Clock`，禁止直接 `now()`** |
| 语言 | 界面与文案必须可翻译；代码与标识符英文 |

> 版本 2.1 修正：早期写的是 Python/FastAPI/Celery/SSE，在用户选定 Java 并决定
> 用数据库状态机替代队列、用轮询替代 SSE 后已作废。`batch-grading/` 是已删除的 v1 历史实现，
> 不受本条约束，也不得作为新代码的参考架构。

## 第九条 — 可运行的验证

- 每个 API 端点必须有测试。
- 核心逻辑必须有单元测试：客观题匹配、总分合成、四态流转、幂等派发、宽限期边界。
- 任何阶段结束时，`make test` 必须全绿；不允许"先提交，测试以后再补"。
- 多 worker 形状的代码必须在多 worker 下验证过一次，不得只在单进程假设下通过。

## 第十条 — 不伪造状态

- 界面与文档中不得出现"已验证""已测试"等表述，除非确有对应的自动化测试或执行记录。
- 未实现的功能必须显式标注为未实现，不得用假数据伪装成可用。
- 视频、图片等不支持自动判分的形态，必须如实说明"需人工复核"。

## 第十一条 — 公网安全

- 全站 HTTPS；会话 Cookie 必须 `Secure` + `HttpOnly` + `SameSite=Lax`。
- 密钥只能来自环境变量或密钥管理服务，**不得写入数据库或代码**。
- 登录、上传、发起批改三类端点必须限流。
- 上传必须校验扩展名与实际内容类型，拒绝可执行文件。
- 生产环境禁止启用开发替身登录；缺少凭据时必须显式失败，不得静默降级为无鉴权。

## 第十二条 — 可观测

- 后端每个请求记录：request_id、user_id、路由、方法、状态码、耗时；
  **不得记录请求或响应正文**。
- 前端记录关键行为事件（页面浏览、提交、发起批改、批准、发布），批量上报。
- 日志与事件保留期可配置，并且必须有清理机制。
- 学生数据不得发送到第三方分析服务。

## 第十三条 — 国际化

- 所有面向用户的文案必须来自可翻译资源，禁止在代码里拼中文句子。
- 后端错误必须同时提供**稳定错误码**与本地化文案。
- 批改反馈的语言由**作业设置**决定，不跟随用户界面语言。

## 第十四条 — 模块边界

系统由**出卷、答卷、阅卷、报告、可观测、认证与班级**六个业务模块组成，
外加一个不含业务的共享层。它们是**可独立变化与独立测试的边界**，不是同一个包里的文件夹。

- **依赖只能单向**：共享层不依赖任何业务模块；认证与班级在最内层；
  出卷、答卷、阅卷、报告、可观测在外层。禁止反向依赖与循环依赖，禁止业务模块之间互相
  引用实现类。
- **跨模块只走端口**：一个模块要读另一个模块的数据，必须通过对方显式暴露的只读接口
  （如 `PaperCatalog`、`SittingLedger`），**不得直接查对方的表、不得跨模块 JOIN**。
  唯一的例外是只读的报告与可观测模块，允许跨模块聚合，但不得写别人的表。
- **表按模块前缀并各有迁移目录**：模块只能写自己前缀的表。新增模块不得修改既有模块的表结构。
- **新业务模块必须能只靠共享层 + 认证 + 班级接进来**，不要求改动出卷/阅卷/报告。
  背单词（word list + 间隔重复）是第一个验证这条的模块：它应当只新增
  `vocab_*` 表、一个一级导航、一组路由，而阅卷模块的文件一行都不改。
  进度（2026-10-21）：`teachloop-vocab` 空模块已接进构建与两道守卫
  （`scripts/check-deps.py` / `scripts/check-boundaries.py`），**尚无表、端口与业务逻辑**；
  表前缀 `vocab_`，规格见 `specs/004-vocab/`。等它承载业务逻辑时，本条的模块计数改成七个。
- 新增跨模块依赖、或让某模块直接读别人的表，**必须先修改本条并说明理由**。

## 第十五条 — UI 与可访问性（2026-10-21 新增）

界面是产品的一部分，不是「最后随便调一下」。以下每一条都有对应的检查或脚本，
写不进检查的约束不算约束。

- **令牌唯一真源**：颜色、字号、圆角、阴影只能来自 `web/src/ui/tokens.ts`（给组件库）
  与 `web/src/styles/tokens.css`（给未迁移的旧页面）。**两处必须是同一份值**，
  由 `scripts/ui/contrast.py` 断言相等。页面与组件里禁止出现颜色字面量。
- **组件唯一入口**：页面只能从 `web/src/ui/` 引组件，**不得直接 `import 'antd'`**。
  这样换实现时改一层，而不是改 21 屏。`scripts/check-ui.py` 守这条。
- **状态必须齐全**：任何交互控件都要有 默认 / 悬停 / 焦点 / 禁用 四态，
  提交类操作另加 加载 态。只做默认态的控件视为未完成。
- **对比度是硬指标**：正文与小字对背景 ≥ 4.5:1，输入框边框与图标 ≥ 3:1，
  亮暗两套主题都要过。数值由脚本算，不靠肉眼「看起来还行」。
- **中文排版**：正文 14px、行高 ≥1.6；**禁止对中文使用 `text-transform:uppercase`
  或靠 `letter-spacing` 装饰**；字号只允许 12/13/14/16/20/24 六级。
- **图标不用 emoji**：统一 `@ant-design/icons`，经 `ui/` 引出。emoji 在不同系统上
  字重、色彩、基线都不一样，是「看着不专业」的直接来源。
- **主题只有亮/暗两套**：同一组语义令牌换值，不另做一套界面。默认亮色，用户选择记在本机。
- **改动必须可验证**：样式相关的改动要附 `/ui-kit` 展示页截图与受影响屏的前后对比；
  没有截图就说「未验证视觉」，不得写「已优化」。

### 品牌层（2026-10-22 补充，决策 006）

- **三个命名空间，不许互相 alias**：`BRAND`（logo 原始色，主题无关，只做填充/插画）、
  `FEATURE_*`（Create / Assess / Practice / Insights 四个功能位的 ink + tint）、
  `STATUS_*`（判分三态 pass / partial / fail）。功能色表达「这是哪个模块」，
  状态色表达「对 / 部分对 / 错」；同一个元素不同时使用两者。
- **亮色只做填充**：`--brand-azure` / `--brand-teal` / `--brand-yellow` 对白分别只有
  3.34 / 2.48 / 1.65，**不得**承担正文、链接、主按钮底或唯一的状态指示；
  界面文字用同族 ink 档（如 `--create` / `--assess` / `--insights`）。
  主操作用压深一档的品牌蓝，亮暗各一个值，白字都必须 ≥ 4.5:1。
- **品牌资产由脚本生成**：logo 只能来自 `scripts/brand/build-assets.py`（源图 sha256 固定、
  去背自检），页面只能通过 `ui/Brand` 组件使用，不得自己拼位图或改色。
- **页头品牌层走映射表**：`PageHeader` 按路由前缀决定 eyebrow 文案与色调；
  页面不得手写功能色或绕开映射表。
- **对比度覆盖功能位与状态**：`contrast.py` 必须包含每个功能位 ink×tint、每个状态
  ink×浅底/白/面板、链接色亮暗各一组；暗色背景从令牌读，不许写死十六进制。
  新增功能色或状态色时同步扩表，否则视为未完成。

## 违宪处理

实现过程中如发现某条原则与需求冲突，**停止并上报**，由人工决定：
修改需求，或修改本宪法。不得私自绕过。
