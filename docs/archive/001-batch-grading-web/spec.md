## 1. 摘要

一个面向教师的多人 Web 系统：教师建立班级与作业、定义 rubric；学生用微信登录后提交作业；
系统对提交批量批改，教师四态复核后发布，学生在系统内看到自己的反馈。

v1 的边界：**多人可用、单租户**（一套部署服务一个教学团队），不含 LMS 对接、不含推送通知与邮件。

## 2. 角色

| 角色 | 能做什么 | 不能做什么 |
| :--- | :--- | :--- |
| **教师** | 建班级、建作业、写 rubric、导入/查看提交、触发批改、复核、发布、导出 | 查看非自己班级的数据 |
| **学生** | 用邀请码加入班级、提交作业、查看自己已发布的反馈 | 看到同班他人任何内容、看到未发布的草稿 |

## 3. 用户故事与验收标准

### US-1 微信登录

作为一名教师或学生，我想用微信登录，这样不用另记一套账号密码。

验收标准：

- [ ] AC-1.1 未登录访问任意页面，跳转到登录页。
- [ ] AC-1.2 点击"微信登录"显示二维码（桌面）或在微信内直接授权（移动端）。
- [ ] AC-1.3 首次登录时选择角色（教师 / 学生），角色存于 `users.role`。
      **修正（2026-10-18，实现时发现）**：原文写「role 由加入班级时的邀请码决定」，
      但存在先有鸡先有蛋问题——教师必须先有账号才能建班、发邀请码，而新用户登录时还没有班级。
      故改为：**角色在首次登录时选择**；邀请码只决定加入哪个班级，不决定角色。
- [ ] AC-1.4 已登录用户再次扫码，复用同一账号，不重复建号。
- [ ] AC-1.5 退出登录后会话立即失效。
- [ ] AC-1.6 开发环境可用本地替身登录，无需微信凭据（见 plan.md 认证抽象）。

### US-2 班级与成员

作为一名教师，我想创建班级并让学生加入，这样作业能按班组织。

验收标准：

- [ ] AC-2.1 教师创建班级，生成一个邀请码。
- [ ] AC-2.2 学生输入邀请码加入，成为该班学生。
- [ ] AC-2.3 邀请码可失效与重新生成。
- [ ] AC-2.4 一位教师可拥有多个班级；一位学生可加入多个班级。
- [ ] AC-2.5 教师在班级页看到学生名单与提交进度。
- [ ] AC-2.6 学生只能看到自己所在的班级。

### US-3 作业与 Rubric

作为一名教师，我想为每个作业写 rubric，这样批改有明确依据。

验收标准：

- [ ] AC-3.1 创建作业时填写：标题、说明、截止时间、满分。
- [ ] AC-3.2 添加评分项：名称、满分、判定说明。
- [ ] AC-3.3 设置篇幅口径：模式（段落 / 分钟 / 不限）、下限、上限、计数说明（自由文本）。
- [ ] AC-3.4 各项满分之和与作业满分不一致时，阻止保存并提示差额。
- [ ] AC-3.5 作业发布后 rubric 锁定；修改需显式确认，且记录审计。

### US-4 提交作业

作为一名学生，我想提交我的作业，这样老师能批改。

验收标准：

- [ ] AC-4.1 支持格式：`.txt` `.md` `.docx` `.pdf` 图片（`.jpg/.png/.heic`）音频视频（`.mp3/.m4a/.wav/.mp4/.mov`）。
- [ ] AC-4.2 单文件上限 100 MB；超限拒绝并提示。
- [ ] AC-4.3 提交后学生看到"已提交"状态；截止前可撤回重交，保留历史版本。
- [ ] AC-4.4 教师可代学生批量导入（历史作业或外部收集），文件名为学生标识。
- [ ] AC-4.5 无文本层的扫描件自动标记 `needs_ocr`，OCR 后转 `ready`；OCR 失败标记 `unreadable`。
- [ ] AC-4.6 无法解析的文件标记 `unreadable`，**不进入评分**，在教师界面单独列出。

### US-5 批量批改

作为一名教师，我想一次批改全班，并看到进度。

验收标准：

- [ ] AC-5.1 在作业页点击"开始批改"，立即返回任务 ID，页面不阻塞。
- [ ] AC-5.2 界面通过 SSE 逐份显示：排队 / 解析中 / 批改中 / 完成 / 失败。
- [ ] AC-5.3 每份作业的客观项（词数、段数、各计数模型段数对照、时长）由代码计算，不经过模型。
- [ ] AC-5.4 模型只负责主观判定与理由，且必须返回符合 schema 的结构化结果。
- [ ] AC-5.5 模型输出不合规时自动重试 1 次，仍失败则标记该份 `failed` 并保留错误原因。
- [ ] AC-5.6 单份超时（默认 180 秒）则跳过该份，继续其余。
- [ ] AC-5.7 批改过程中关闭浏览器，任务继续；重新打开可恢复进度。
- [ ] AC-5.8 `unreadable` 的作业不参与批改与平均分。

### US-6 四态复核

作为一名教师，我想逐份确认 AI 结果，这样最终成绩由我负责。

验收标准：

- [ ] AC-6.1 每份草稿可标记为：批准 / 小改 / 大改 / 驳回。
- [ ] AC-6.2 修改分数或理由时，保存动作写入审计日志（改前、改后、时间、操作者）。
- [ ] AC-6.3 "批准"后才可发布给学生；未批准的草稿学生不可见。
- [ ] AC-6.4 驳回后可填写原因并重新触发单份批改。
- [ ] AC-6.5 支持按状态筛选（待复核 / 已批准 / 已驳回）。
- [ ] AC-6.6 篇幅判定为"边界敏感"时（不同计数模型会导致合格/不合格翻转），界面显式提示教师确认。
- [ ] AC-6.7 教师可批量批准，但每一份仍各自留审计记录。

### US-7 学生查看反馈

作为一名学生，我想在系统里看到老师发布的反馈。

验收标准：

- [ ] AC-7.1 反馈发布后，学生在作业页看到"有新反馈"提示（v1 = 系统内通知）。
- [ ] AC-7.2 学生只能看到自己的反馈，接口层面强制校验归属。
- [ ] AC-7.3 反馈包含：各评分项得分、总评、优点、建议。
- [ ] AC-7.4 未发布或已撤回的反馈，学生访问返回 404 而非 403（不泄露存在性）。

### US-8 导出

作为一名教师，我想导出成绩与反馈。

验收标准：

- [ ] AC-8.1 导出 ZIP：逐份反馈文本 + `class_summary.txt`。
- [ ] AC-8.2 导出成绩 CSV：学号/姓名、各项得分、总分、状态。
- [ ] AC-8.3 导出内容与界面一致，且只包含已批准的反馈。

## 5. 非功能需求

| 类别 | 要求 |
| :--- | :--- |
| 性能 | 单批支持 ≥ 40 份；SSE 首个事件 ≤ 1 秒；列表接口 P95 ≤ 300 ms |
| 并发 | 批改并发数可配置，默认 3；单个任务失败不影响其他 |
| 安全 | 会话 httpOnly + SameSite=Lax；写操作校验 CSRF；上传白名单；越权返回 404 |
| 隐私 | 遵守宪法第七条；不记录作业正文到应用日志 |
| 可用性 | 全中文界面；批改进度断线可恢复；错误给出可执行提示 |
| 可维护 | 认证/OCR/引擎三处可替换；数据库变更走迁移 |
| 可观测 | 每个批改任务有 ID，可追到每次模型调用与耗时 |

## 6. 边缘情况

| 情况 | 期望行为 |
| :--- | :--- |
| 扫描件无文本层 | 标记 `needs_ocr`；不得判 0 分 |
| OCR 失败或置信度低 | 标记 `unreadable`，教师界面单列，可手动转录 |
| 视频缺 `ffprobe` | 标记时长未知，要求人工确认，不估算 |
| 学生截止后重交 | 允许但标记"迟交"；是否计分由教师决定 |
| 教师批改中学生改了提交 | 正在批改的版本不变；新版本另起一次批改，旧结果保留 |
| 同一 openid 加入两个班 | 同一用户，多班级成员关系 |
| 微信未返回昵称 | 用"学生-{短 ID}"占位，允许后续修改 |
| 批量批改中途服务重启 | 重启后任务标记 `interrupted`，可一键续跑未完成项 |
| 模型输出不是合法 JSON | 重试 1 次；仍失败标记 `failed` 并保留原始输出供排查 |
| 两项满分之和与总分不符 | 保存时阻止并提示差额 |
| 教师试图发布未批准草稿 | 阻止并提示需先批准 |
| 学生访问他人反馈 | 返回 404 |
| 上传超大文件 | 拒绝并提示上限 |
| 审计日志与当前分数不一致 | 以审计日志最后一条为事实来源，界面提示不一致 |

## 7. 假设（未经用户确认，可在实现前推翻）

| 编号 | 假设 | 影响 |
| :--- | :--- | :--- |
| A-1 | 班级加入方式 = **邀请码** | 影响 US-2 与数据模型 |
| A-2 | 微信登录使用**开放平台网站应用扫码登录**；移动端可后续加公众号网页授权 | 影响认证实现 |
| A-3 | v1 对象存储用**本地目录**，接口与 S3 兼容以便切换 | 影响部署 |
| A-4 | v1 通知 = 页面内红点/列表，不含推送与邮件 | 影响 US-7 |
| A-5 | 单租户：一套部署对应一个教学团队 | 影响权限模型 |
| A-6 | 学生用微信登录（假设学生均有微信） | 影响登录页设计 |

## 8. 阻塞输入（需用户提供才能联调，不阻塞开发）

| 编号 | 需要什么 | 缺失后果 |
| :--- | :--- | :--- |
| B-1 | 微信开放平台 **AppID / AppSecret** | 只能用开发替身登录，真实扫码无法联调 |
| B-2 | 已备案的**授权回调域名** | 微信回调校验不通过 |
| B-3 | 决定是否允许云 OCR（涉及学生数据外传） | OCR 只能停留在本地实现 |

> 开发策略：认证与 OCR 都以接口抽象，**缺 B-1/B-2 不影响 v1 用开发替身跑通全流程**；
> 一旦凭据到位，只需配置即可切换到真实微信登录。
