# 决策 008 — 没有 rubric 的作文按「内容 80% + 语法与拼写 20%」判

日期：2026-10-22　状态：已实现　相关：T368、D-28、AC-27.20、FR-085、
`teachloop-grading/.../prompt/EssayRubricWeights.java`、
`teachloop-app/src/main/resources/application.yml`（`teachloop.grading.essay-default-rubric`）

## 问题

用户 2026-10-22 晚的一句需求：「AI 逐篇按各自 rubric 判分，基本上就是：把题目整个内容塞给 AI
（80% 分数），再加上一点基本的语法和拼写检查（20% 分数）就可以了。这个百分比，弄成 config，
可配置修改。」

这暴露两个现状问题：

1. 老师（尤其是导入的真实卷子）根本没有逐题写 rubric 的时间与信息。题项级 rubric 为空、
   试卷级 rubric 也为空时，旧实现会编一份「内容要点 / 语言准确性」的默认 rubric，**但没有分值**，
   判分侧只能把满分平均分给两项（50/50），与「内容是大头、语法是小头」的直觉相反。
2. 这个比例不该写死在代码里，用户要能改。

## 决策

| 项 | 决定 |
| :--- | :--- |
| 默认两项 | **内容与任务完成** + **语法与拼写**。内容项看是否完整回应题目、覆盖要点；语法项只看基础语法、拼写与标点 |
| 默认比例 | 内容 **80%**，语法与拼写 **20%** |
| 配置 | `teachloop.grading.essay-default-rubric.content-percent`（默认 80，取值 1–99）；语法与拼写自动取 `100 − X`，**只留一个旋钮**，避免两个值互相矛盾。环境变量 `TEACHLOOP_ESSAY_CONTENT_PERCENT` |
| 生效范围 | **只在题项级 rubric 与试卷级 rubric 都为空时**合成；老师写了 rubric（带分值）就永远用老师的 |
| 分值拆分 | 按本题满分拆：15 分 → 12 + 3；14 分 → 11.2 + 2.8；70% 配置 → 10.5 + 4.5。两项相加必须等于满分 |
| 题目全文 | 始终放进 prompt 的「题目要求」（`stem` 原文），不截断、不摘要 |
| 语言 | 反馈语言是 `en` 时 rubric 文案用英文，否则中文 |
| 非法配置 | 启动失败（`IllegalArgumentException`），不静默按 50/50 兜底 |

## 为什么不把默认 rubric 写进试卷

导入时就把 12/3 写进题项，会让「事后改配置」对旧卷子无效；而且老师在第 4 步看到的是一份
看似自定义、其实是系统生成的 rubric，容易误以为改配置没用。现在的分工是：

- 没写 rubric → 判分时按当前配置合成（配置改了，下一次判分就生效）；
- 想要固定比例/细则 → 在第 4 步给那道题写自己的 rubric（题项级，永远优先）。

`PaperCatalogImpl` 同时移除了「伪造一份无分值默认 rubric」的旧逻辑——否则它会盖住这里的默认，
被按 50/50 均分。

## 后果

- 旧卷子（快照里带着旧版系统伪造的那段「内容要点 / 语言准确性」、没有分值）在判分时被识别为
  「没有 rubric」，按新的 80/20 合成，不需要重新布置；老师自己写的 rubric 不受影响。
- 复核页的 AI 评分项会显示两项：`内容与任务完成 x/12`、`语法与拼写 y/3`（以 15 分题为例）。
- 没有 rubric 的作文不再有「篇幅/词数」评分项；词数与段数仍作为客观指标进 prompt，
  但不由模型单独给分（不再有长度项）。

## 验收

- `EssayRubricWeightsTest` 6/6（默认 80/20、小数不丢分、70% 配置、英文文案、旧伪造 rubric 识别、非法值报错）。
- `AiGradingEngineTest` 10/10（无 rubric 时 prompt 含题目全文与 12/3 两项；70% 配置给出 10.5/4.5）。
- 老师 rubric 优先：`AiGradingEngineTest.gradesEachEssayWithItsOwnRubric` 仍按各题 rubric 判分。
