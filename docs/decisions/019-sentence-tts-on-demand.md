# 决策 019 — 例句朗读：本地引擎 + 按需合成 + 服务端开关

日期：2026-10-24　状态：生效（T429 起实现：后端 text/lang + 前端每句喇叭）　相关：AC-57.6、AC-57.8、AC-57.9、T429、§9、A-2

## 问题

原 spec 把例句朗读排除在 V1 之外（§9：只朗读单词本身，理由是 TTS 成本与断句质量）。
2026-10-24 用户提出：TTS 用的是本地引擎，没有按次费用，例句旁边也应该放喇叭让学生跟读。

## 事实核对：成本结构

- 引擎是 `local` + `piper`（`127.0.0.1:5002`），**不经过任何按字符计费的接口**，每次合成的边际费用是 0 元。
- 真正要算的是三件非按次的事：

| 项目 | 量级 | 说明 |
| :--- | :--- | :--- |
| CPU | 一句 3 秒音频，普通 CPU 上合成约几百毫秒（量级估算） | 播放时多占一点核，服务器本来就在跑 |
| 存储 | 22.05kHz / 16bit / 单声道 = 44KB/s，3 秒约 130KB | 1000 词 × 6 句 ≈ 0.78GB；按需缓存只算听过的 |
| 带宽 | 与播放时长成正比 | 点播，不是预加载 |

- 用户规模：英文撑死 1000 人；中文/西语目前只有用户儿子一人。
- 中文/西语的 Piper 模型各几十 MB，要随 sidecar 一起部署；缺模型时回落浏览器语音。

## 决定

1. **引擎**：保持 `local` / `piper`，不引入 `cloud`。
2. **合成时机**：**点击才合成**（首次），不随内容预生成。
3. **缓存**：键 = `sha256(文本 | 语言 | 音色 | 语速)`，写 BlobStore；只写播放过的句子。
4. **开关**：`teachloop.vocab.tts.sentences.enabled` 默认 **true**，环境变量 `VOCAB_TTS_SENTENCES_ENABLED`；
   前端通过 `GET /api/vocab/config` 的 `sentenceAudio` 决定是否渲染喇叭；关掉后端点对 `text` 返回 404。
5. **范围**：明细页与复习卡里可见的例句都带喇叭；释义整段不朗读。

## 为什么不是全量/预生成

- **存储从「按播放量」变成「按词表量」**：80,579 形 × 6 句 × 130KB ≈ 60GB，而大部分词没人听。
- 预生成要把文本生成与音频生成两条链路耦合，任一边失败都会拖慢另一边；按需合成失败时前端还能回落浏览器。
- 用户的规模是 1000 人以内，点播的并发压力可以忽略。

## 代价与边界

- **首播等待**：冷启动几百毫秒，前端必须有加载态，失败回落 `SpeechSynthesis`（现有 `SpeakerButton` 已有该路径）。
- **端点要扩**：现在只认 `form` 且硬限 64 字符（`TtsAudioEndpoint.java:67-68`）；要加 `text`（≤200 字符）、`lang`，与 `form` 互斥，超长返回 400。
- **缓存键要加文本维度**：否则句子与单词撞键。
- **断句质量**：Piper 对 6–18 词的短句可用，长句语调平——这也是只读例句、不读释义的原因。
- **磁盘随播放量增长**：`BlobStore` 只有 store/load，没有 list/delete/TTL；只写播放过的句子，增长与真实播放量挂钩。
