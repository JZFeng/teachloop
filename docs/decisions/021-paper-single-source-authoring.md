# 决策 021 — 试卷录入：Markdown 原文是唯一内容源（四步向导）

日期：2026-10-25　状态：已拍板、待实现　相关：D-34、AC-4.3 / AC-4.9 / AC-4.10 / AC-4.17④ /
AC-4.23④ / AC-4.24–4.29、FR-146–150、T456–T466、
`docs/research/2026-10-25-paper-authoring-single-source.md`、决策 007（题项级 rubric）、
决策 009（试卷级 rubric 退役）

## 问题

用户 2026-10-25 要求重新梳理 `/papers` 录入流程：

> 内容很多，我们先定需求，先定好 spec。去掉导入考试这个 button。流程要简化。

现状（`web/src/teacher/PaperWizardPage.tsx`，2374 行、5 步 + 3 张内容卡）：

1. 第 2 步要老师**手工建部分**（标题 + 每题分值），再在第 3 步**逐题建题项**（题号、题型、分值、
   题干、选项、标准答案），第 4 步再**建评分项**。而真实卷子本来就是一个文档，
   `teachloop-paper/src/test/resources/exam/english-grade10-2026-with-answers.md`
   里题号、选项、答案、分值、命题人、审题人、总分全都写着——系统让人把这些**再录一遍**。
2. 双源必然漂移：第 2 步的「部分」与原文的「第X部分」是两份数据，第 3 步的答案是第三份。
   表单也表达不了材料（阅读篇章/完形短文）、多空题、写作任务里的内容要点，
   现有做法是把材料拼进每道题题干（D-12），重复且难改。
3. 「导入考卷」是独立页面（`PapersPage.tsx:114` → `/papers/import`），
   与向导第 2 步的「上传整卷导入」卡重复做同一件事，还自带一个「粘贴答案表」面板。
4. 第 3 步（标准答案）在答案已经随原文导入之后没有存在意义；
   「批量改题型」也只是在补解析器的判断，而不是老师的真实需求。

## 决策

| 项 | 决定 |
| :--- | :--- |
| 内容源 | **Markdown 原文是唯一内容源**，题项是它的投影。第 2 步只留一个 `VditorMarkdown` 编辑器（源码 / 所见即所得互切，复用新建作业页的同一组件） |
| 内容入口 | 只有一个按钮 **「生成考题」**：编辑器文本与上传文件（`.docx/.md/.txt/.xlsx`）走同一个按钮；删掉「内容（部分）」「上传整卷导入」「批量改题型」三张卡、`/papers/import` 页面与「导入考卷」按钮 |
| 重新生成 | **替换重建**：清空本卷的部分 / 题项 / 评分项后按原文重建；已发布卷禁止（服务端也拒绝）。已有内容时二次确认，**必须数出三类会丢失的界面内编辑**：rubric 已填的题数、错题解析状态非 `none` 的题数、旧 `section_criteria` 行数（三项都为 0 不弹）；重建前写一条快照，每卷保留最近 3 条 |
| 进度 | 不确定型进度（阶段文案 + 已用秒数），**不显示伪造百分比** |
| 解析结果 | 生成后一张**只读**预览表（部分 / 题号 / 题型 / 分值 / 题干 / 标准答案 / 状态）+「N 题 · 合计 X 分 · 缺答案 K 题」；不做逐题编辑 |
| 步骤 | 5 步 → **4 步**：① 基本信息 ② 内容 ③ 评分项 ④ 预览与发布。第 3 步（标准答案）删除 |
| 基本信息 | 新增**目标总分**（可空，发布校验）、**命题人**、**审题人**（自由文本；命题人默认当前教师显示名） |
| 第 4 步 | **一题一 tab**：每个 `ESSAY` 题项一个 tab，一个编辑器 + 合计预览；保存只发 `rubricMarkdown`；**取消参考范文输入**；不再创建 `section_criteria` |
| 预览发布 | 评分项列不再出现 `—`：无 rubric 显示「无」（en `N/A`），写作题按 `<题号> <内容>` 分块、块间空行；保留「同步并校验」「发布试卷」，同步只校验不建内容 |

## 为什么

- **单源**：老师手上的就是一份文档。让系统接受那份文档，比让人拆成三层表单再录一遍便宜得多；
  真实卷的 77 题、150 分、两道写作题都已在原文里（AC-4.21 已能按节建 `ESSAY` 题项）。
- **替换重建**：调研（`docs/research/2026-10-25-paper-authoring-single-source.md` §3）确认这在题库类产品里没有先例，可参照的只有 ClassMarker「按 ID 导回」；评审因此定了三条护栏：确认框数出三类会丢的界面内编辑、重建前留快照、已发布卷禁止重建。
- **替换重建**：第 3 步删掉之后，「改一道答案」的唯一路径就是改原文再生成。
  如果重导仍按现状「题号已存在就跳过」（`PaperEndpoint.java:540-560`），改原文将**永远不生效**，
  于是这个流程会把老师锁死在第一次解析结果上。替换是唯一自洽的语义，代价（界面内补的 rubric 会丢）
  用确认框和「rubric 也写进原文」来兜。
- **只读预览**：它不承担编辑职责，只回答三个问题——解析漏题了吗（题号断档）、答案配错了吗（缺答案）、
  分值算对了吗（合计）。可编辑的预览会重新制造双源。
- **目标总分不覆盖自动合计**：`papers.total_points` 由题项 + 评分项算出（`recalcTotal`），
  判分信封与快照都用它；把老师填的 150 直接写进去会让「卷面分值」和「实际判分总分」两套数打架。
  目标值只当发布闸门（AC-4.26）。
- **命题人/审题人用自由文本**：identity 没有教师名录接口，v1 也不需要按人统计；
  一个 `varchar(80)` 就能满足「卷子上要印名字」。真要做账号级追责再单独立项。
- **tab 而不是动态 step**：草稿里的 `step` 是数字（`PaperWizardPage.tsx:166`），
  动态步数会让恢复与「上一步」语义随卷子变化；tab 不动 stepper，且只挂载当前 tab 的 Vditor
  （Vditor 是独立的 296 KB 懒加载 chunk）。
- **参考范文退出界面**：用户明确「不需要参考范文了，没有必要」。D-25 当初的定位是「可选、只给教师看」，
  可选的东西长期没人填就不该占一块编辑器；`reference_markdown` 列、解析与复核页展示保留。

## 影响与兼容

| 面 | 影响 |
| :--- | :--- |
| 数据库 | 迁移 `V065`（V064 已被并行的 vocab lists 占用）；`papers` 加四列：`target_total_points numeric(8,2)`、`author_name varchar(80)`、`reviewer_name varchar(80)`、`content_markdown text`；全部可空，不回填（旧卷没有原文，无法重建）。新增 `paper_content_snapshots(id, paper_id, created_at, reason, payload jsonb)`，每卷只留最近 3 条 |
| 接口 | 新增 `PUT /api/papers/{id}/meta`；`POST /{id}/import` 与 `/{id}/import/text` 增 `replace`；`POST /publish` 增三条服务端校验；`ImportResult` 增 `contentMarkdown` 与 `metaHints` |
| 旧卷 | `content_markdown` 为空 → 编辑器空 + 提示「旧流程录入，没有原文」，预览表照常显示服务端题项；发布退回旧规则（只校验总分 > 0） |
| `section_criteria` | 列与接口保留（复核页仍读旧数据）；界面不再创建；替换重建会删掉本卷的 criteria，确认框里明示 |
| 参考范文 | `objective_items.reference_markdown` 保留、解析保留、复核页可读；向导不再写 |
| 路由 | `/papers/import` 删除，旧书签落到 404 页；`POST /api/papers/{id}/answers` 接口保留但界面不再提供入口 |
| 测试 | 后端沿用 Mockito 端点测试（`PaperImportEndpointTest` 构造重载）；前端纯函数抽到 `web/src/teacher/paperFlow.ts` 用 `node --test` 覆盖 |

## 未采纳的替代方案

| 方案 | 为什么不 |
| :--- | :--- |
| 保留表单录入，只是把步骤合并 | 双源照旧；真实卷的材料/多空/写作任务仍然表达不了 |
| 重导只追加、题号重复跳过（现状） | 改原文永远不生效，第 3 步已删后没有修正路径 |
| 逐题 diff：同题号更新、消失的删除 | 边界最多（跨部分移动、部分改名、rubric 迁移），收益只省一次点击。ClassMarker 的「导出→改→按 Question ID 导回」是唯一成熟的按 ID 覆盖做法，代价是多一轮文件往返（调研 §2） |
| 两段式：先 dry-run 预览、再确认提交 | 预览与写库必须共用同一次解析结果（AC-4.25④），两段式要么解析两次（结果可能不同）、要么缓存解析结果（多一份状态）；确认框里已经给出「将删除」的准确数字，缺的只是「将新建 M」，收益低于复杂度 |
| 目标总分直接覆盖 `total_points` | 与 `recalcTotal`、判分信封冲突 |
| 命题人/审题人选教师账号 | 需要 identity 新开名录接口 + 下拉 + 空态，v1 无统计需求 |
| 每道写作题一个 step | 草稿 `step` 语义随卷子变，恢复/上一步要重写 |
| 服务端真流式进度 | 解析是同步的，几十毫秒级；假百分比反而误导，用不确定进度 + 阶段文案 |
