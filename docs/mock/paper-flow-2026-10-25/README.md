# 试卷录入原型 · Markdown 单一内容源（2026-10-25）

可点击的单文件原型，用来定**需求与流程**，不是实现。对应决策 `docs/decisions/021-paper-single-source-authoring.md`
（D-34）与 `specs/002-v2-platform/spec.md` 的 AC-4.9、AC-4.24–AC-4.29。

## 怎么打开

双击 `index.html` 即可（`file://` 就能跑，无构建、无依赖、无网络）。
顶部五个入口对应 `试卷库 / ① 基本信息 / ② 内容 / ③ 评分项 / ④ 预览发布`；
每个向导页顶部有一排**演示状态**按钮，用来切到空白 / 生成中 / 成功 / 失败 / 锁定等界面。

## 数据从哪来（不许手抄）

- 试卷标题、命题人、审题人、总分、77 道题的题干、选项、标准答案、分值、部分结构，
  全部来自真实卷 `teachloop-paper/src/test/resources/exam/english-grade10-2026-with-answers.md`。
- `build-data.py` 负责抽取，产物是 `data.js`（`window.PAPER`），页面只读这份数据：

  ```bash
  python3 build-data.py     # 77 题 / 合计 150 分 / 缺答案 0 题
  ```

  脚本自己会校验「抽出来的合计 == 卷面总分 150」，对不上直接退出。
- 材料型题目（七选五 36–40、完形 41–55、语法填空 56–65）按 AC-4.16 把材料并入题干、
  空位按出现顺序标成 `___题号___`；这与后端 `PaperTextParser` 的输出形状一致，
  但**不是**调用生产解析器（生产解析器有自己的一套单测）。
- 两类**示例**内容，页面底部也写了：
  1. 第 3 步两份 rubric 是老师会填的样子（每题合计 15 分），不是原文里的内容；
  2. 试卷库列表的后两行是示例数据（真实只有一行）。

| 屏 | 状态 / 变体 | 这一点在定什么 |

## 明确没做（原型不是实现）

- 不真的解析文件、不真的写库；「生成中」是定时器模拟的（点了「演示状态」会冻结，方便截图）。
- 不画学生端、布置页、导入校对页；这些页面本次不改。
- 撤销重建没有按钮：快照存在库里，v1 只用于误删恢复（AC-4.24⑥）。

## 与旧 mockup 的关系
