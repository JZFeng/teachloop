# 教师邀请码原型（2026-10-30）

对应需求：教师入驻走邀请码（承接 `AC-3.2`）、`AC-3.3` 改成「真升级、只能升自己」。
单文件、无依赖、无构建：**双击 `index.html` 就能点**。演示数据全部是假的（侧栏底部有标注）。

## 这一版在回答什么

1. **管理端那块放哪、长什么样**：放在系统设置页里的一个区块（`/admin/ai` 现在就是"系统设置"枢纽，通讯通道也挂在那儿），不新开页面。
2. **码是一次性弹窗还是常驻列表**：常驻列表 + 未过期可复制 / 发错可撤销。只弹一次的码，刷新后管理员自己都找不回来（今天 `GET /api/admin/teacher-invites` 还不存在）。
3. **学生端入口放哪**：`/profile` 资料卡下面独立一块「我有教师邀请码」，不是塞进资料表单里。
4. **两条腿都要有**：已登录的学生填码升自己；还没账号的新老师可在注册页凭码开户（否则"真升级"意味着老师必须先装作学生注册一次）。
5. **升级后要不要重新登录**：不要。侧栏立刻变（切换「升级后」那一屏看）。

## 屏与深链

| 屏 | 深链 | 重点看什么 |
| :--- | :--- | :--- |
| 管理端 · 邀请码 | `#admin` | 生成 / 列表（可用·已兑换·已过期·已撤销）/ 复制 / 撤销；下面一块把 5 条规则写死 |
| 学生端 · 填码升级 | `#redeem` | 输入 8 位码 → 成功态 + 侧栏当场变成教师；四种失败文案（无效 / 已过期 / 已兑换 / 已撤销） |
| 注册页 · 凭码开户 | `#register` | 公开页无壳层；邀请码是**可选字段**，填了建教师账号、不填建学生 |
| 升级后 | `#after` | 侧栏多出教师菜单（带「新」标）+ 顶部成功提示 |

演示码：`K7QM4XZP`（可用）、`2FB9WDRT`（可用）；其余三条分别演示「已过期 / 已兑换 / 已撤销」。
右上角「重置演示」把状态打回初始值。

## 定稿参数

| 项 | 值 | 说明 |
| :--- | :--- | :--- |
| 码形 | 8 位，去掉易混字符（无 `0/O/1/I`） | 与后端 `AdminService.newCode()` 的字母表一致 |
| 有效期 | 3 天 | 后端 `createTeacherInvite(me.id(), 3)` 已经是这个值 |
| 归属 | 生成它的管理员 | `TeacherInvite.createdBy` 已有 |
| 撤销 | 未兑换才可撤销 | 已兑换的码不撤销账号（撤账号走「停用账号」） |
| 列表 | 常驻，含状态与兑换人 | 需要补 `GET /api/admin/teacher-invites`（今天只有 POST） |
| 升级语义 | 登录态 → 只升自己，忽略请求体邮箱 | `AC-3.3` 新语义；非 STUDENT 返回 409 |
| 未登录 | 码 + 邮箱 + 密码 → 建 TEACHER | 旧路径保留，同一个码、同样一次性 |
| 提权边界 | 码只能升到 TEACHER，永不 ADMIN | `AC-3.5` 不变；管理员由管理员在后台授予（下一份 spec，014） |
| 审计 | 每次成功兑换写一条 | 谁 / 什么码 / 何时 / 从哪个角色 |

## 这一版需要你拍的三件事

1. **管理端位置**：放「系统设置」页里的区块（本原型）还是单开 `/admin/teachers`？前者省一个路由，后者以后好加「用户列表 + 改角色」。
2. **注册页的码**：做成可选字段（本原型）还是单独一个「我有教师邀请码」入口页？字段少一步，入口更显眼。
3. **升级后是否立刻刷新菜单**：本原型是「立刻变、不用重新登录」。实现上要顺手把 `web/src/api/features.tsx` 的 effect 依赖加上 `me?.role`，否则侧栏不重取（现在只依赖 `me?.id`）。

## 取舍

- 平板（≤1023）把侧栏收成抽屉，原型里直接收起 —— 与 `web/src/styles/app.css` 同一个断点，不自造第三档。
- 邀请码不做二维码、不做一键发送（没有可用的 IM 通道）；复制到剪贴板后由管理员自己发。
- 不做「批量生成」：一个人一天发不出十张码，批量是替没出现的场景造功能。
