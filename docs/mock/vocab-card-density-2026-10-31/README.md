# 词卡密度两版 Mock（2026-10-31 · word-details / review-back）

> 目标：把「构词与派生」从**每行 1 个词**改成多列，让「核心理解」回到首屏。
> 本目录只有静态原型，**没有改任何业务代码**；`web/`、`teachloop-*/`、locales 均未改动。
> 页头与卡片外骨架按真实实现取数：`.app-main` 1240 / 34px、卡片列 820、卡片内边距 36×40、`.review-card-toolbar` 24/2/40。

## 1. 结论

**推荐 V2**（派生词 / 词形变化 各 2 列，词族 3 列）。若要让 iPad 也一处不折行，再按 §3.4 给词族加一条 ≤1100 的 2 列回落 —— 那条**没有内置进 mock**，等你定。

一句话数字锚点：卡顶 →「核心理解」标题，现状 **733px** → V1 **432px** / V2 **458px**（1440 桌面）；但在 **834×1194（iPad 竖屏，项目硬性验收断点）** 上，V1 **507px**、V2 **495px** —— **V1 反而更高 12px，还多 3 个换行格**。

即：V1 在桌面赢 26px，在平板上输 12px + 6 处换行。学生多数只有 iPad（AGENTS.md 的平板必检条目），所以选 V2。

## 3. 坏处与临界点（数字，不是形容词）

### 3.1 桌面（1440）：V1 最紧那一格只剩 0.7px

| 组（列数） | 最紧的一项 | 列宽 | 实占 | 余量 |
|---|---|---|---|---|
| 派生词 3 列（V1） | `inflexional adj. 屈折的（英式拼写）` | 213.3px | 212.6px | **0.7px** |
| 词形变化 3 列（V1） | `inflected 过去式/过去分词` | 213.3px | 150.7px | 62.6px |
| 词族 3 列（**两版相同**） | `inflexional adj. 屈折的（英式拼写）` | 213.3px | 211.5px | **1.8px** |
| 派生词 2 列（V2） | `inflexional adj. 屈折的（英式拼写）` | 325px | 219.1px | **105.9px** |
| 词形变化 2 列（V2） | `inflected 过去式/过去分词` | 325px | 150.7px | 174.3px |

所以「`inflectional adj. 屈折的` 在 3 列下会不会换行/挤压」：**1440 下不会换行，但真正贴边的是 `inflexional adj. 屈折的（英式拼写）`，只剩 0.7px；`inflectional` 是第 2 宽的项（147px，余 66px）。**

### 3.2 换行只由「卡片内宽」决定，iPad 正好落在换行区

3 列要放下最宽项需要**卡片内宽 ≥ 736px**（列宽 212.6 × 3 + 列间距 20 + 标签列 64 + 间距 14）。

| 视口 | 卡片宽 | 卡内宽 | 3 列列宽 | 换行 |
|---|---|---|---|---|
| > 1100（桌面固定卡） | 820 | 738 | 213 | 0 |
| 1100 – 888 | 视口 − 68（≥ 820） | ≥ 738 | ≥ 213 | 0 |
| 886（实测边界） | 818 | 736 | 213 | 0 |
| **884（临界点）** | 816 | 734 | 212 | **派生词开始换行** |
| **834（iPad 竖屏）** | **766** | **684** | **195** | **派生词 3 + 词族 3** |

834 下卡片只有 766px（`834 − 34×2`），比桌面固定卡 820 还窄 54px，卡内 684 − 标签列 78 = 606，三列只剩 **195px** —— 比最宽项需要的 212.6px 少 17.6px，所以 V1 的派生词和两版共有的词族都会换行（截图 `shots/v1-834.png` 里能直接看到「屈折变化；语调变 / 化」被折断）。

### 3.3 字号/字体一变，V1 的 26px 优势就没了（1440）

| 字号增量 | V1 换行格 | V1 卡顶 → 核心理解 | V2 换行格 | V2 卡顶 → 核心理解 |
|---|---|---|---|---|
| +0（本 mock） | 0 | **432px** | 0 | **458px** |
| +0.25px | 1 | 452px | 0 | 459px |
| +1px | 4 | 498px | 1 | **486px** |
| +2px | 6 | 532px | 3 | **518px** |

**+1px 之后 V2 反而比 V1 矮**（486 < 498）：V1 的 26px 是把每格压到 0.7px 余量换来的，字宽一变大就连本带利还回去。

### 3.4 V2 自己的坏处，以及一条建议

- **桌面多一行 26px**：7 行 vs 6 行，卡顶 → 核心理解 458 而不是 432。
- **词形变化留 1 个空格子**：3 项排 2 列 = 2 行（2+1），第二行右侧空着。
- **词族 3 列是两版共有的软肋**：834 下列宽 195px，词族换行 3 项（V1、V2 都是这 3 项）。这一条跟选哪版无关，需要单独拍板。三种缓解方案实测（834×1194）：

  | 方案 | 834 卡顶 → 核心理解 | 834 换行格 | 代价 |
  |---|---|---|---|
  | 原样（词族 3 列） | V1 507 / V2 495 | 6 / 3 | 视觉折行，行高不齐 |
  | **词族在 ≤1100 降 2 列** | V1 496 / **V2 484** | 3 / **0** | 与「词族三个词一行」的原话不一致 |
  | 标签列改成组上方的小标题（回收 78px） | 未测（每组多一行 ≈ +25px） | 0 / 0（列宽 221） | 三组各加一行，把省下的高度还回去一部分 |

## 8. 残余风险

1. **834 下两版都还没干净**：3 列在 195px 列宽下必然折行，V2 剩 3 处（词族）。要么接受折行，要么按 §3.4 给词族加 ≤1100 的 2 列回落（834 下 0 折行、再矮 11px）。这一条需要你拍板，mock 没有擅自加第三个版本。
2. **未在 Windows / iOS Safari 实测**：所有字宽数字来自 macOS Chromium + PingFang SC。§3.3 的表就是给这个用的——V1 只要字宽增加 0.3% 就换行，V2 要增加 48%。
3. **v0 是复刻基线，不是真实页面读数**：去掉页头文案与真实数据差异后，「733px」是可复核的同口径基线；真实页面还有 `morphology` 的 `structure`/`chain` 行（本词为空，不渲染），绝对读数可能不同。
4. **只接了 `inflect` 一个词**：更长的派生词（如 `unbelievably`）会让 3 列更早换行；建议实现时对 item 加 `min-width: 0` 并保留换行（不省略号），再用 2–3 个长词回归。
5. **`pointer: coarse` 下图标放大到 44px 已写进 mock**，但截图是桌面 pointer，触屏下的工具栏高度未截图验证。
6. **1100–888 区间卡片反而更宽**（视口 − 68 > 820），这是真实 `.review-card-column { flex: 1 1 auto }` 的既有行为，mock 照抄、未修正。
