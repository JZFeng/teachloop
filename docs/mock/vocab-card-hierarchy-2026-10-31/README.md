## 1. 结论

**推荐把方案 5（参考稿方向）当默认卡背**，义项用 B（三行编号）。

数字锚点：方案 5 的「核心理解」仍在首屏 **107/107px 全部可见**（标题 top 221px），换来的是 8 个词形从「贴在一起的文字」变成 **8 张可扫读的卡片**（2 列 × 364px，词性做成 Tag）；代价是整卡 1255 → **1440px（+185）**，且 1440×900 下「构词与派生」整块掉到首屏外（首屏读完的区块 **2 → 1**）。

五个方案各自解决的是不同那一半问题：

| 方案 | 解决什么 | 可复核证据 |
|---|---|---|
| p1 | **内容重复** | 词族 8 条 → 重复行 **7 → 0**（0 个新词），卡顶→核心理解 432 → **153px** |

### 3.1 方案 5 的义项排法 A / B / C

| 排法 | 长什么样 | 释义区高度 | 卡顶 →「核心理解」 | 整卡高度 | 834 折行 | 首项字号/字重 |
|---|---|---|---|---|---|---|
| **A** | 一行，三项用「；」连排（参考稿 / 现状写法） | **22px** | **176px** | 1395px | 0 | 14 / 400 |
| **B**（p5 默认） | 三行编号列表，`v.` Tag 在第一行行首，三项左边缘对齐到 Tag 之后 | **67px** | **221px** | 1440px | 0 | 14 / 400 |
| **C**（可选） | 义项 1 单独一行 15/650 当主释义，2、3 缩进 13.5/400 `--muted`，不加分隔线 | **70px** | **224px** | 1443px | 0 | 15 / 650 |

**一句话结论：推荐 B**（+45px，释义区 22 → 67px，两个断点都不折行）。可复核理由：A 在 834 下能一行放完，但余量只有 **132px**（实测文本宽 518px / 可用 650px ≈ 9 个汉字），释义再长 9 个字就会折成没有结构的 2 行；B 每项独占一行，与内容长度无关。C 只比 B 贵 3px，但把义项 1 提到 15/650，会和 15px 的区块标题同字号、层级反而打平——所以 C 留作可选，不做默认。

## 4. 每案代价（数字说话）

**方案 1（去重 + 重排）**：76px 标签列 + 16px 间距 = 92px 永久占宽（两列只剩 318px）；层级一点没动（释义与标题都是 16/650）。好处很硬：重复行清零、核心理解提前 279px。

**方案 2（去掉标签列）**：组名各占一行 → 卡高 **+44px**；+46px/列在 2 列布局下没有功能收益（本来不折行）。唯一硬收益在「词族条件显示」：834 下 p1 内容区 592px → 每列 190.7px（最宽词条约 219px，必折行），p2/p3 内容区 684px → 221.3px（0 折行，余量约 2px）。

**方案 3（视觉层级）**：是全站卡背共用类的改动（复习卡背一起变）；5 条分隔线 + 每块 22px 上内距使卡高比 p1 长 **66px**；例句喇叭默认隐藏，触屏要靠 `@media (pointer: coarse)` 常显兜底。

**方案 4（极简首屏）**：多一次点击，「构词与派生」默认不可见；展开后比 p3 多一条 66px 折叠入口。

**方案 5（参考稿方向）**
1. **卡片边框 = 视觉噪音**：8 张卡各 1px 边框（hover 变蓝），在 414px 高的「构词与派生」里是 9 条横线 4 条竖线；同一张卡上已有 5 条区块分隔线，两套线条会互相削弱（建议实现时把卡片边框降到 `--line-2`，本次保持 `--line`）。
2. **词性 Tag 会与其它 Tag 混用**：这个浅灰 Tag 和导航、筛选器里的 Tag 长得像，需要一条「Tag 只表示词性」的用法约定，否则以后会被误用成状态标签。
3. **`auto-fill` 列宽会跳**：见 §5.4，视口 1050 与 1100 之间从 2 列跳到 3 列，并且 1050 下卡片反而更宽（445px），不是单调变化。

## 5. 方案 5（参考稿方向）

= 方案 3 的全部决策 + 用户点名的四点 + 你补的落地细节。

### 5.1 四点怎么落地的

| 参考稿的做法 | 本 mock 的落地 | 为什么改 |
|---|---|---|
| 词性 `v.` 做成浅灰 Tag（`#f3f4f6` / `#6b7280`，圆角 4px） | 浅灰 Tag 用 `--panel-2` + `--muted`，12px/600，圆角 4px；释义行和单词卡片用**同一个** Tag | 用项目 token，不抄 tailwind 值；两处同款才不会看起来像两种标签 |
| 每个单词独占一个卡片（flex + 1px 边框 + 6px 圆角） | 卡片：1px `--line` 边框、6px 圆角、9px/11px 内边距，单词 15/650 + 词性 Tag + 释义 13 `--muted`；hover 边框变 `--accent` | 照做；顺手把「词形变化」的三项也做成卡（参考稿本来就这样），所以那三项补了 `v.` 词性 |
| 组名用 emoji（🔄 / 🌳）+ 14px 大写 | 组名 12.5px/600/`letter-spacing .5px` + **内联 SVG 线性图标**（16px、stroke 1.75、currentColor：`git-branch` 给派生词、`repeat` 给词形变化） | **项目红线「禁止 emoji 当图标」**——这是与参考稿唯一的偏离，见 §5.2 |
| 区块标题 18px 黑字 + 4px 蓝色竖条 | 标题 15/650 + 4px `--accent` 竖条（竖条挂在卡片左留白里，标题文字仍与正文左对齐） | 沿用 p3 的 15px 字阶；竖条只做「板块引导」，不做第二层放大 |

### 5.2 与参考稿的唯一偏离

参考稿的组名带 emoji（🔄 词形变化 / 🌳 派生词 / 💡 信息条），本项目红线是「**禁止 emoji 当图标**」（`AGENTS.md` UI 约束第 3 条）。所以换成 16px 线性 SVG（stroke 1.75、currentColor），形状按语义选：派生词 = 分支（git-branch），词形变化 = 循环（repeat）。除此之外没有功能或结构上的偏离。

### 5.3 颜色与圆角（token 化）

`#2563eb → --accent #1A63E0`、`#f3f4f6 → --panel-2`、`#eff6ff → --accent-weak`、`#e5e7eb → --line`。圆角用了 **12（卡片）/ 8（信息块、核心理解）/ 6（单词卡片）**。

> ⚠️ 一个规范冲突要你知道：**词性 Tag 的 4px 圆角**是你指定的、也是参考稿的值，但项目 UI 约束写的是「圆角只有 12/8/6 三档」。mock 里先按你的 4px 做；若要守死规范改成 6px，12px 小字上只差 2px，视觉几乎不变。

### 5.4 834 下的列数（含 auto-fill 跳列）

网格是 `repeat(auto-fill, minmax(300px, 1fr))` + 10px gap。实测：

| 视口 | 卡片宽 | 卡内宽 | minmax(300px) | minmax(280px) |
|---|---|---|---|---|
| 1440 | 820（固定） | 738 | **2 列 / 364px** | 2 列 / 364px |
| 1100 | 1032（撑满） | 950 | **3 列 / 310px** | 3 列 / 310px |
| 1050 | 982 | 900 | **2 列 / 445px** | **3 列 / 293px** |
| 1000 | 932 | 850 | 2 列 / 420px | 2 列 / 420px |
| **834（iPad 竖屏）** | 766 | 684 | **2 列 / 337px** | 2 列 / 337px |

- **834 是两列，337px/卡，不需要 280px 兜底**（两种 minmax 结果完全一样）。
- 会跳列的是 **1010–1070px 这一段**：1100 三列（310px）→ 1050 两列（445px）→ 1000 两列（420px），卡片宽度随视口变窄反而变宽。要消掉跳变得把 auto-fill 换成固定 `repeat(2, 1fr)`（代价：宽屏也只有两列，卡片会被拉到 445px 甚至更宽）。

### 5.5 信息条：浅蓝块 vs 无底色注脚

| 写法 | 整卡高度 | 视觉 |
|---|---|---|
| **浅蓝信息块**（p5 主版，贴近参考稿） | **1440px** | 卡片上出现**两块浅蓝**：信息条 + 核心理解蓝框，同色同面积，互相抢注意力 |
| 无底色注脚（= 方案 3 的写法） | **1416px**（−24） | 只有核心理解一块色块，「核心理解」才是唯一被强调的东西 |

高度差只有 24px，差别在注意力分配：**两块浅蓝会互相抢注意力，方案 3 的注脚写法更克制**。建议二选一：信息条降回注脚，或改成 `--panel-2` 灰底（灰 ≠ 蓝，不与核心理解撞色）。

### 5.6 义项排法（A / B / C）

数据见 §3.1；默认 B，`?senses=a` / `?senses=c` 可切。

## 6. 两个可以马上定的细节

**释义 14 还是 15？** 卡顶→核心理解 **176 / 178px**、整卡 **1255 / 1257px**，差 2px；差别纯在层级：14px 时「正文 < 区块标题（15px）」有字号差，15px 时只能靠 400 vs 650 的字重区分。建议 14。

**词族条件显示时的 3 列**：本版删了词族，上一版「词族 3 列在 834 贴边」的问题暂时消失；但只要出现「词族含额外词」的词，3 列会回来——p1 布局 834 下每列 190.7px（必折行），p2/p3 布局 221.3px 才刚好放下。这条决定「要不要同时做方案 2」。

## 7. 音标合并的保留逻辑

**合并条件**是英/美两份 IPA 字符串完全相同（inflect 都是 `/ɪnˈflekt/`），此时只印一份、后面跟 UK / US 两个小喇叭；**假设英/美不同**（例如 better 的 `/ˈbetə/` vs `/ˈbetər/`），仍显示「英 /ˈbetə/ 🔊 美 /ˈbetər/ 🔊」两段——这个页面的音标是给人跟着念的，宁可重复也不能缺一份。mock 里两态是同一份 DOM，只靠 CSS 显示其中一段。

11. 五方案 `main` 的 DOM 完全一致（只换 `body[data-scheme]/[data-expanded]/[data-info]/[data-senses]`）。

## 11. 残余风险

1. **未在 Windows / iOS Safari 实测**：字宽来自 macOS Chromium + PingFang SC；p5 卡片在 834 下 337px，最宽词条约需 219px，余量充足；但 `auto-fill` 的列跳变（§5.4）在别的字体下边界会移动。
2. **词性 Tag 的 4px 圆角破了「只许 12/8/6」的规范**（§5.3）：要么破例一次、要么统一成 6px。
3. **两套线条会互相削弱**：区块分隔线 5 条 + 卡片边框 8 条在 p5 里同时存在；建议实现时把卡片边框降到 `--line-2`。
4. **p5 整卡 1440px**：比 p3 长 185px，1440×900 下「构词与派生」整块落到首屏外；如果不能接受，用义项 A（−45px）或回落到 p3。
5. **触屏兜底只在 CSS 里**：`@media (pointer: coarse)` 让例句喇叭常显，但截图都是桌面 pointer，iPad 真机未验。
6. **词族规则依赖数据侧**：mock 只演示「重复就不显示」，真正判断（词族是否含额外词）要在内容生成/前端做。
7. **例句 / 近义词 / 词源是示意内容**：结构可信，措辞不是最终文案。
