# 协作最佳实践（2026-10-23 复盘）

> 由 `docs/reports/retro-2026-10-23/` 的 4 天复盘提炼，每条都对应一次真实事故。
> `AGENTS.md` 只保留摘要，这里是完整版；改动前先看复盘报告里的证据。

## 汇报

- 触发条件与三行格式见 `AGENTS.md` 的「进度汇报」一节（连续 8 次工具 / 超过 120 秒的命令 / 一个可验证单元完成）。
- `job_list` 里 running 超过 10 分钟且没有输出，先查是不是僵尸进程再报，不要把「进程还活着」当成「正在干活」。
- 临时服务用完 `kill`，并写一行「已清理」；遗留的 8012/5175 曾让用户以为任务跑了 3 小时。

## 完成度

- 「完成」必须分三档：接口完成 / 界面入口完成 / 端到端验收完成。没做浏览器验收就写「仅结构校验」。
- 新增页面必须写清「从哪个页面、点什么、到哪个 URL」。用户 10 秒找不到入口，算未交付。
- 交付带可核对数字（对/错/分、用例数、行数），不写「已改好」。
- 4 天里 3 次「完成」被当场质疑、4 次「造得出、找不到入口」，都出自把接口跑通当成交付完成。

## 动手前

- 用户说「先讨论 / 先别改」时，只复现、定性、给方案对比，代码不动，等拍板。
- 收到「回归缺陷 / bug」先要可复现的输入（URL、记录 id、导入源文件），再翻 `git log`；先排除数据问题。
- 用户判断错了，用证据纠正，不照着错误判断改。
- 证据：「标准答案泄露」实为篇目标签 A–D 拼进题干；一次「回归」查了 70 分钟，最后是用户自己的数据问题。

## 输入与规则

- 外部输入（试卷 md、答案表、富文本）先收 3 份真实样例进 `docs/rubrics/fixtures/` 并接进测试，再改解析；每修一个解析缺陷，同轮把该样例加进夹具。
- 静默丢弃即缺陷：截断、丢弃、降级、替身引擎，都必须回报「第 N 行 / N 条，原因」。
- 同一规则只允许一处实现（长度上限、空标记、评分项选择），其余引用同一常量。
- 证据：解析器一族缺陷 4 天里重复 5 次；80 字符上限静默丢分；`env.sh` 的 stub 默认值让 QA 悄悄降级。

## 视觉决策

- 颜色、布局、观感的决策先出可点样张或并排对比图，再问；不写纯文字问卷。
- 证据：导航着色 6 题问卷全部被跳过，用户回「文字我看不出效果啊」；品牌视觉先出 4 屏样张，用户回「哇，你太伟大了」。

## 并行会话

- 多个任务并行时按 `docs/process/parallel-tasks.md` 执行：一个任务一个 worktree + 短命分支 + 一个属主，分支当天合回。
- 同一工作目录同一时刻只允许一个写入会话；提交前看 `git status` 里的别人未提交改动，不替别人提交；测试红了先排除并行未提交改动的污染。
- 证据：两个会话同一分钟改 `scripts/env.sh` 造成假归因；一条未提交改动把另一场会话的全量测试打红。

## 记账

- 「改了主意」先写 `docs/decisions/NNN-*.md`，再改代码。
- commit 必须引用 `specs/*/tasks.md` 里存在的 T 号；T 号全局唯一。
- 一个可测单元一个提交，不做上万行的单体提交。
- 验收标准当轮勾选，并写清这次验了哪几条 AC。
- 改完就提交：每次改动后创建一个 commit，只提交本次修改的部分；不许 `git add -A`，不把别人或无关的未提交改动扫进来。
- 证据：决策 006 比代码晚约 20 分钟；296 条 AC 一条没勾；002 与 006 各有一个 T341；T180–T197 一次提交 10,728 行。

## 安全

- 不把 API Key 贴进对话；已贴过的立刻轮换。
- 不对仓库跑 `find ... -delete` 一类通配删除。
- 证据：用户两次把 Key 贴进对话（未进仓库，但留在本机会话归档里）；`find -delete` 误删过已提交文档，靠 git 历史救回。

## 文档数字

- README、PROGRESS、交付状态里的计数（测试数、AC 数、模块数、决策范围）由 `scripts/status.sh` 生成或校验，不手抄。
- 证据：`AGENTS.md` 曾写「九个模块」而实际 10 个；README 的 FR 65 / 任务 224 / 决策 001–008 各差 1。
