## 0. 开项目第一天：风格声明（4 行，10 分钟）

**问题**：「现代、简洁、专业」这类形容词对 AI 和人都无效——无法验真，每次解释都不同。

**四行约束**（写进项目根的 `AGENTS.md`，在写第一个页面之前）：

1. **一句话风格 + 一个可参照的实物**：「Ant Design 企业后台的密度，Linear 的克制」。
   不给实物，AI 会自由发挥成「通用后台蓝」。
2. **三个数字**：主色 `#1A63E0`、圆角只有 12/8/6 三档、正文最小 14px 且对比度 ≥4.5:1。
3. **一条禁令**：渐变、彩色投影、emoji 当图标、手写 `btn` 类名。
4. **一个唯一入口**：组件只能从 `web/src/ui/` 引，颜色只能从 `web/src/ui/tokens.ts` 取。

**为什么这四行管用**：本项目自身的数据——003 写过「教育行业稳重」这句风格，没拦住紫色渐变
加彩色投影（`docs/research/2026-10-21-design-system.md` 的「项目起点」记录了 `--accent:#4f46e5`
的 `linear-gradient` + 彩色投影）；真正拦住它的是 AC-27.4 那条 grep 断言。
**形容词定方向，断言定结果。**

## A 组 · 结构（骨架对不对，最像「没设计过」的地方）

### A1 主操作的作用域分离（两个检查点，缺一不算过）

**A1a · 页面级**：这屏里唯一希望用户点的按钮是哪个？

- **怎么量**：数页面级容器（`PageHeader` 的 actions、表单底部、工具栏）里的实色填充按钮。
- **通过**：≤1 个（全局导航不算）。
- **改法**：其余降为次要或文字按钮；并列动作收进 `RowActions` 的「⋯」。

**A1b · 行内级**：表格行、列表项里的按钮，视觉权重有没有真的低于页面级？

- **怎么量**：取一个行内按钮和一个页面级按钮的 `className`，看**除 size 外还有没有差别**。
- **通过**：行内动作**不得复用页面级的 primary 填充**。`RowActions` 的 main 槽位保持
  `default`（描边），`text`（无底色）用于更轻的查看类动作。
- **不过的典型**：一屏同时出现 `ant-btn-primary` 与 `ant-btn-primary ant-btn-sm`——
  颜色、文字色、hover 色完全相同，只差 8px 高度。扫视时两个蓝块争同一注意力预算。
- **改法**：行内降为 `default` 或 `text`；**不要**去删掉行内动作（那是功能，不是装饰）。

> **为什么 A1b 必须单独列**：只有 A1a 时，一个 20 行的表格会报「21 个主按钮」，
> 建议方向是「删掉多余的主按钮」——错的，那些行内动作删不得。真正的修法是**降级**而不是删除。
> 反例来自 2026-10-26 的实际观察：`/vocab/lists` 里「新建词单」（页面级 primary）
> 与「开始复习（10）」（行内 primary small）同屏同色。

- **锚点**：`web/src/ui/Button.tsx:9`（文档原文：「primary 主操作，一屏只该有一个」）、
  `Button.tsx:11`（「text 表格行内、工具条上的轻操作」）、
  `web/src/ui/RowActions.tsx:66`（main 槽位默认 `default`）、AC-25.1。

### A2 层级只靠三样东西

- **自问**：这些层级是靠字号、颜色深浅、留白做出来的，还是靠加框、加阴影、加粗堆出来的？
- **怎么量**：数一屏里用了几个不同的边框颜色和阴影值。
- **通过**：边框只有 1–2 档（`--line` / `--line-strong`），阴影只有 `--shadow` 一档。
- **改法**：拆掉多余额外边框，改用留白分组。
- **锚点**：`web/src/styles/tokens.css` 的 `--line` / `--shadow`。

### A3 内容对齐到一条线

- **自问**：把页面左边缘画一条竖线，有几块内容不在线上？
- **怎么量**：目视，或用 DevTools 量各块内容区的 `padding-left`。
- **通过**：同一层级的内容左边缘只有 1 个值。
- **改法**：统一到容器 padding，删掉块级自带 margin。

### A4 间距来自刻度

- **自问**：这些 padding / margin 是不是 4 或 8 的倍数？
- **怎么量**：grep `margin: [0-9]+` / `padding`,或 DevTools 逐个看。
- **通过**：同层级只用 1–2 个值，且都是 4/8 倍数。出现 13 / 17 / 23 / 420 这类值即不过。
- **改法**：换成最近的刻度值。
- **锚点**：本项目历史违规实例——`PaperWizardPage.tsx` 的 `margin: '6px 0'`、`paddingLeft: 20`。

### A5 字号不超过 4 级

- **自问**：这屏有几个字号？
- **怎么量**：`grep -oE 'font-size:\s*[0-9]+px'` 加页面内联样式。
- **通过**：≤4 级，正文 ≥14px（表格密度可以降到 12–13）。
- **改法**：并级，靠字重和颜色区分，不靠字号。
- **锚点**：页面标题 24px（006 取代 003 的 20px）。

### A6 一屏要填满

- **自问**：屏幕底部有多少比例是空白？
- **怎么量**：截一张真机尺寸的图，看内容占比。
- **通过**：内容占视口 ≥60%；表单类页面居中限宽，不要顶部堆一块、下面一片空。
- **改法**：加宽字段、并成两列、把下一步动作放进可视区底部。
- **锚点**：`docs/reports/brand-app-2026-10-22/paper-wizard-light.png`——2158px 高，卡片只占上半屏。

## B 组 · 一致性（同类长得一样，对应「接口契约」）

### B1 同一操作同一组件

- **自问**：这个按钮/表格/提示，全站别处是不是同一个实现？
- **怎么量**：`grep -c 'className=.*\bbtn\b'`（手写类名数）；`grep -c 'RowActions\|DataTable'`。
- **通过**：非 `web/src/ui/` 下手写 `btn` 类名 0 处；表格只有 `DataTable.tsx` 一处实现。
- **改法**：换组件，不要在页面里补 className。
- **锚点**：AC-27.1、AC-68.1、`make check-ui` 的 `LEGACY_BTN_CLASS` / `RAW_TABLE` 规则。

### B2 颜色只来自令牌

- **自问**：这屏有没有写死 `#xxxxxx` 或 `rgba(...)`？
- **怎么量**：`make check-ui` 的 `COLOR_LITERAL`；或 grep `#[0-9a-f]{6}`。
- **通过**：除 `tokens.ts` / `tokens.css` 外 0 处。**当前全仓实测 0 处。**
- **改法**：加令牌，不要在页面里写色值。
- **锚点**：AC-27.1、`web/src/ui/tokens.ts:1` 的注释即规则书。

### B3 图标同一套，不用 emoji

- **怎么量**：`make check-ui` 的 `EMOJI_ICON`。
- **通过**：0 处。**当前实测 0 处。**
- **改法**：从 `web/src/ui/icons.tsx` 取。
- **锚点**：AC-27.6。

### B4 同类状态用同一组件、同一位置

- **自问**：别的页面加载中是居中还是骨架屏？出错是在顶部还是原地？
- **怎么量**：grep 各页用没用 `Loading` / `ErrorState` / `Empty` / `InlineNote`。
- **通过**：四类状态组件各只有一处实现，位置固定。
- **锚点**：`web/src/ui/States.tsx`、`web/src/ui/InlineNote.tsx`、AC-28.1。

## C 组 · 状态完备（边界条件，后端最熟）

### C1 五态齐全

- **自问**：空、加载、出错、无权限、超长文本，这五个我见过哪一个？
- **怎么量**：逐个数，缺一个记一个。
- **通过**：列表与表单页五态都有可见呈现。
- **改法**：补 `Empty` / `Loading` / `ErrorState`；超长用 `showOverflow`。
- **锚点**：AC-68.2（表格空态）。

### C2 禁用要有原因

- **自问**：这个灰掉的按钮，用户知道为什么点不了吗？
- **怎么量**：找 `disabled`，看旁边有没有 `reason` 或说明。
- **通过**：禁用项在菜单/提示里能读到原因。
- **锚点**：AC-25.5。

### C3 失败不许灰字，且要说下一步

- **自问**：出错时这行字和普通说明长得一样吗？说了该改什么吗？
- **怎么量**：`make check-ui` 的 `MUTED_FAILURE`；再看 401/429/5xx 是否分开文案。
- **通过**：失败用 `InlineNote` 的 error/warning 档；同类失败给不同下一步。
- **锚点**：AC-70.1–70.2、`docs/decisions/026-message-tones.md`（四档判据）。

### C4 表格四件套

- **自问**：能排序吗？看得出当前排序方向吗？有页脚吗？空的时候说什么？
- **怎么量**：点表头；清空数据。
- **通过**：`aria-sort` 正确、页脚有「共 N 条 · 第 x/y 页」、空态有文案、行有悬浮。
- **锚点**：AC-68.2、`web/src/ui/DataTable.tsx`。

## D 组 · 可读性（硬指标，最容易被当成「审美」争论）

### D1 对比度

- **怎么量**：DevTools 取前景/背景色，或用 `python3 scripts/ui/contrast.py` 复算。
- **通过**：正文对背景 ≥4.5:1；边框、图标、大字 ≥3:1。**当前 44 组全部达标。**
- **反例**：antd 默认输入框边框 `#D9D9D9` 只有 1.41:1，本项目改成 `#8C8C8C`（3.36:1）。
- **锚点**：AC-29.2、AC-29.3、`scripts/ui/contrast.py`。

### D2 可操作性

- **怎么量**：只用 Tab 走一遍主流程；量目标元素尺寸。
- **通过**：焦点环可见、Tab 顺序符合阅读顺序、触达 ≥44×44（触屏）、Esc 能关弹层。
- **锚点**：AC-29.1、AC-29.4。

### D3 平板与两个断点（2026-10-28 新增）

**为什么单列一条**：项目里 90% 的评审是在 1440 宽的桌面上做的，而学生多数只有 iPad。
2026-10-28 的实测事故就是这么来的——登录页在 iPad Pro 12.9 竖屏（1024×1366）上整块卡片悬在屏幕中间，
表单标题落在页面 34% 处；而 ≤900 时侧栏被 `display:none` 后**没有任何导航**（`nav` 只存在于 `<aside>` 里）。

- **怎么量**：固定 6 个视口，每个视口量三件事——
  1. `document.documentElement.scrollWidth > innerWidth + 2`（横向溢出）；
  2. 每个可见 `button / a / [role=button]` 的 `getBoundingClientRect()` 宽高（触达尺寸）；
  3. `getComputedStyle(document.body).fontSize`（正文 ≥14px）。

  | 视口 | 宽×高 | 该验的断点 |
  | :-- | :-- | :-- |
  | 桌面基线 | 1440×900 | ≥1101：两栏登录、侧栏常驻 |
  | iPad Pro 12.9 竖 | 1024×1366 | 1024–1100：登录单列；侧栏仍常驻（断点 1023） |
  | iPad Pro 12.9 横 | 1366×1024 | ≥1101 的反向验证 |
  | iPad Air 11 竖 | 834×1194 | ≤1023：侧栏抽屉 + 顶栏「菜单」 |
  | iPad 10 竖 | 820×1180 | 同上 |
  | iPad mini 竖 | 744×1133 | 同上（最窄） |

- **通过**：横向溢出 **0**；正文 14px；可点元素 ≥44×44，**表格内的文字链接是已知例外，但行必须有整行可点或行末按钮**；
  抽屉四条关闭路径（按钮 / 遮罩 / Esc / 选中导航）都成立。
- **当前实测（2026-10-28，10 页 × 6 视口 = 60 组，本地 5173 同一份构建）**：横向溢出 **0/60**、字号 **14px 全通过**；
  **未通过**：`/papers` 26/35、`/grading` 14/27、`/classes` 13/22 个可点元素高度 <36px（最小 16px，全是表格标题文字链）——
  触屏上难点，属待修项而不是已修项。
- **锚点**：`web/src/styles/app.css` 的 `@media (max-width: 1100px)` 与 `@media (max-width: 1023px)`；提交 `a350d87`。

## 提意见的三段式（照这个说，没人能当你是外行）

> **违反什么（引用规则或数字）→ 后果是什么（用户会怎么做错）→ 改法是什么**

- 差：「这个页面太丑了。」
- 好：「这屏有 4 个同权重主按钮（违反一屏一个主操作），用户不知道该点哪个；建议保留『下一步』为主，其余降次要。」
- 好：「这行错误是灰字，和旁边的说明同色（违反 C3），用户会当成普通提示划过去；要换成 `InlineNote` 的 error 档。」

## 七个病灶名（有了名字，意见就是判断而不是口味）

| 名字 | 一句话 | 快速识别 |
| :-- | :-- | :-- |
| 魔数间距 | 不用刻度的 padding/margin | `13px` `17px` `420px` |
| 字号通胀 | 一屏五六个字号 | grep `font-size` 去重 |
| 状态缺失 | 只做了成功路径 | 拔网线看页面 |
| 同权竞争 | 多个主按钮抢注意力 | 数实色按钮 |
| 对比不足 | 灰字讲错误、浅灰当边框 | 量对比度 |
| 层级堆框 | 靠加边框/阴影分组 | 数边框色 |
| emoji 混入 | emoji 当图标 | `EMOJI_ICON` 规则 |

## 边界（这套清单不能做的事）

1. **不能判「好不好看」**。风格、品牌调性、配色的高级感，这 18 条一条都管不了。
   那部分不靠你的直觉，靠令牌系统加一个参照产品，不要让任何人临场发挥。
2. **静态判不全**。示范评审那次（17 条版本）只有 9 条能靠源码判定；D3 是脚本可判的，其余仍必须上浏览器。
   所以「仅结构校验」和「端到端验收」是两档，不许混说（见 `AGENTS.md` 完成度三档）。
3. **守卫会误报**。`RAW_TABLE` 规则当前会把注释里的 `<table>` 算成违规
   （实例：`web/src/exam/importToEditor.ts:10`）。看到红先看是不是误报，再决定改代码。

## 自查命令（交付前跑一遍）

```bash
make check-ui                      # 8 条硬规则 + 基线
python3 scripts/ui/contrast.py     # 44 组对比度
echo "手写 btn: $(grep -rc 'className=.*\bbtn\b' web/src --include=*.tsx | awk -F: '{s+=$2} END {print s}')"
```

D3 的平板矩阵目前是手动跑（不新增依赖：DevTools 设备模拟或 ego 脚本切 `deviceMetricsOverride`）。
在任一设备视口下，控制台粘这两行就得到两个数：

```js
document.documentElement.scrollWidth > innerWidth + 2                     // true = 横向溢出，必须修
[...document.querySelectorAll('button,a,[role=button]')].filter(e => e.offsetParent)
  .map(e => e.getBoundingClientRect()).filter(r => r.height < 36 || r.width < 36).length   // 小触达个数
```

按 D3 表格的 6 个视口各跑一次：横向溢出必须为 0；小触达个数记进评审记录（当前存量见 D3）。
