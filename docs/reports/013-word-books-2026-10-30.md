## 3. 关键口径（都是可复核的实现决定）

1. **`BOOK` 来源的判重靠 `batch_id` 填书 id。** `uk_vocab_word_sources` 是
   `(word_id, kind, assignment_id, set_id, batch_id)`，不含 `book_id`。把书 id 放进 `batch_id` 后，
   这个键恰好是「一个词对一本书一条来源」：重复加入不堆行，同一个词来自两本书各一条（plan §11 待定 2 的答案）。
2. **副本词单先建、再写词。** 词单上限（默认 100）与同名冲突在任何词条写入之前暴露，不留「词进了库但没副本」的半成品；
   空书也能返回 `listId`（形态与 AC-102.1 一致）。
3. **覆盖率 `readyCount` 可为 null**：内容包与 delta 都不可用时回 null（界面显示「—」），不是 0%
   （0% 会被读成「这本书没做内容」，实际是「查不到」，plan §6）。`BookRef` 是 int，端口侧降级为 0。
4. **`CreateRequest.fromStart` 改成 `Boolean`**：Jackson 3 默认 `FAIL_ON_NULL_FOR_PRIMITIVES`，
   只传 `{"listId": ...}` 时基本类型收到 null 会抛 500（写测试时实测发现，已修）。
5. **`/review-sessions` 的 1000 词分批不重叠**：同一 `listId` 的前序会话里出现过的词会被跳过；
   一轮背完再从头开始（不会因为「都背过」卡住学生）。

## 5. 必须贴的两组实测数字

### 5.1 加入幂等（`VocabBooksTest#joinIsIdempotentAndKeepsProgress`）

书 5 词，其中 2 词已在学生词库且带进度（`REVIEW` / `LEARNING`）：

```
[013] 首次加入 book=81c22b29-… created=3 duplicated=2 total=5 listId=6234d3fc-…
[013] 二次加入 book=81c22b29-… created=0 duplicated=5 total=5 listId=6234d3fc-…
```

同一份用例还断言了：`vocab_progress` 的 `state/due_at/interval_days` 前后逐字段相等；
`vocab_generation_jobs` 行数前后相等且没有任何指向这 5 个词的任务（`on-import=true` + `engine=stub` 下，
真调了 `enqueueNewWords` 就会多出任务）；`vocab_word_sources` 里该书恰好 5 条 `kind='BOOK'`；副本词单恰好 1 份且名为 `书名 (2)`。

### 5.2 同一段文本：加词页 vs 书导入页（`VocabBooksTest#importParityAndEntryCounts`）

夹具含 markdown 标题、表格、全角 `ｈｅｌｌｏ`、大小写、变音符、重复行、80 字符超长行：

```
[013] 同一段文本：加词页 cleanups=0 skipped=4 tokens=10 书导入 cleanups=0 skipped=4 tokens=10
[013] 书导入提交 total=10 created=4 duplicated=4 failed=2；二次提交 created=0 duplicated=8
```

断言口径：两边的 `cleanups`、`skipped`、`lineCount`、`distinctWords` 数量与 `preview` 的**字段名集合**逐条相等
（`cleanups`/`skipped` 是整棵 JSON 结构相等，不是只比数量）；非法行（>64 code point）`failed` 计数且不写库；
同一段文本二次提交 `created=0`、词条数不变。

> `cleanups=0` 是因为这段夹具里的清洗都落在「被跳过的行」上（表格与说明行），不是清洗逻辑没跑——
> 两边相等才是 AC-100.6 要的东西；`DictionaryTextParser` 的规则没有任何一处被复制。
