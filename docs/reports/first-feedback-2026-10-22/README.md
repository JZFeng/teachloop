# 首批教师反馈修复（2026-10-22，T324–T328）

一轮反馈 10 条，按「现象 → 真因 → 改法」记录。截图都在本目录。

## 1. 评分标准不能 prefill

- 现象：新建作业页一打开，评分标准里已经有一段英文 2/4/4 rubric（篇幅 / 立场 / 解释与细节），
  与教师这次要布置的作业毫无关系。
- 真因：`AssignmentCreatePage` 的初始 state 直接取了 `teacher.assignmentCreate.defaultRubric`。
- 改法：初始值改为空字符串；评分标准变必填并给出「一条一行、分值写在行里、各项合计 = 总分」的提示与占位示例。
  后端 `DEFAULT_ASSIGNMENT_RUBRIC` 保留（仅服务老接口/存量），界面不再预填。

## 2. / 3. 「导入 .md」不像按钮、位置不对

- 现象：只是一行灰字，且落在 textarea 下方。
- 改法：换成组件层 `Button`（带上传图标），通过 `Field` 新增的 `extra` 槽位放到「评分标准」标签行右侧。
  导入后直接替换编辑器内容，行尾统一成 `\n`。

## 4. 「AI 将看到」下面那一堆不相干的东西

- 现象：展开后把 rubric 原文又打印一遍；因为当时是预填的英文默认值，所以「什么都没输入也有一大堆」。
- 改法：不再重复原文。改成按后端 `RubricValidator` 同一套规则解析出的**评分项 + 每项分值 + 合计 vs 总分**，
  一致时为「合计与总分一致，可以发布」，不一致/缺分时给出具体提示。空状态只说格式。

## 5. 参考范文（可选，锚点）→ 参考范文（可选）

文案改动，zh/en 同步。顺带修掉占位示例里把 `\n` 当字面量显示的问题。

## 6. 首页「最近作业」的班级列变成一串 UUID

- 现象：`bd12ab5e-a4a0-3cce-81af-182ef76a6daa、624edf5f-…`，而 `/classes` 里只有自己建的两个班。
- 真因：`GET /api/offerings` 对教师**返回全站已发布的布置**，这些布置挂的是别的老师的班；
  前端 `classNamesText` 解析不到班级名就退化成裸 UUID。班级接口本身是对的（按 `teacherId` 过滤），
  数据不一致的根因在布置列表没有按归属收口。
- 改法：列表只返回 `created_by = 自己`（ADMIN 仍看全部）；`detail` / `submissions` / `class-summary`
  加归属校验（越权 404）；`V035` 把 V030 加列之前的空 `created_by` 按参与班级的唯一属主回填（QA 回填 4 条）。
  前端再加一道保险：解析不到班级名显示「班级信息未加载」，不再打印 UUID。

## 7. 班级页点「成员」被跳到空白页

- 现象：点击后整页全白，侧栏也没了。
- 真因：`GET /api/classes/{id}/members` 返回 `{studentId, displayName, submissionCount}`（T042），
  前端仍按 `string[]` 渲染，把对象当成 React 子节点 → React 19 卸载整棵组件树。
- 改法：加 `ClassMemberView` 类型，成员表显示「姓名 / 学号 / 本班提交数」；另加路由级 `ErrorBoundary`
  （按 pathname 复位），以后任何渲染崩溃只坏一块，侧栏与「重新加载」还在。

## 8. 评分标准想直接写 Markdown（而不只是 textarea）

- 现象：两个真实文件（`评分标准1.md` / `评分标准2.md`）导入后提示「评分项合计 8 分，作业总分 14 分」。
- 真因（两个，都是解析器误杀，不是格式问题）：
  1. `是否…` 开头的问句式评分项被 `RubricVocabulary.isDecision` 当成 Yes/No 判定行丢掉；
  2. 名称超过 80 字符被静默丢弃 —— 教师第 2 条（6 分）是 95 字符的整句问句，于是 14 分只剩 8 分。
- 改法：`是否` 视为问句不再判为判定行；名称上限 80 → 200（仍能挡住整段散文）。
  前后端解析规则同步（`web/src/components/rubric.ts` 与 Java 逐字段一致）。
- 编辑器选择：**Markdown 编辑器（工具栏 + 编辑/预览），不是富文本**。理由：AI 读的就是 Markdown 原文，
  内容按标题/列表/分值解析；富文本存 HTML 会被后端白名单洗掉结构，反而更容易丢分值。

## 9. 题目要求也支持 Markdown

- 同上的 `MarkdownEditor`（`#` 标题、`-` 列表、`**加粗**`、编辑/预览两个 tab）。
- 学生端作业页把题目要求与评分标准从 `pre-wrap` 纯文本改成 Markdown 渲染（`Markdown` 组件，纯 React 元素、
  无 `dangerouslySetInnerHTML`，链接/图片/HTML 一律当文字）。

## 10. 导入 `AI立即.md` 报「第 141 行：无法解析的答案行『11. challenging』」

- 现象：填空题答案被当成选择题答案报错，用户认为是回归。
- 真因：这份卷子「七选五」一节写了 5 个空，但只有 7、8 两道题。导入器对「有材料没题号」的小节按空顺推题号，
  5 个空占用了 7–11，后面完形填空真正的 9/10 撞号、语法填空的 11 不存在，答案区 `11. challenging`
  找不到对应的填空题，于是按选择题解析失败。
- 改法：先扫描卷面**自带题号**的题，填空分组顺推时遇到已被占用的题号就停，并给一条「还有 N 个空未成题」的告警。
  现在这份文件解析出 1–14 题、答案 `A B A C D B G A A B / challenging anxiety to walk impressive`、
  缺答案 0；`PaperTextParserTest` 23/23（含该卷回归用例）。
- 顺带：粘贴文本导入改成与文件导入同一套预处理（剥 Markdown 记号），否则整卷 md 粘进去时「第X节」认不出来，
  会重现同一类题号串号问题。
