# Mockup 对等性审计 · 统一协议

需求基线：`specs/002-v2-platform/mockups/interface.html`（21 个 `.screen`，已 review 通过）。
实现基线：`web/src/**`（React + Vite，路由见 `web/src/App.tsx`）。
后端：`teachloop-*/src/main/java/**`（判断「页面缺」还是「接口缺」时必须看）。

## 一、审计方法（逐屏做，不许跳）

1. **页面级**：mockup 这个 screen 在实现里有没有对应路由/入口？入口在导航里能否到达？
2. **控件级**：把 mockup 屏里的每个可交互元素 / 数据列 / 状态标记 / 按钮 / 提示文案列成清单，
   逐条在实现里找落点：
   - 字段级：每个表格列、每个表单字段、每个统计卡都要找到对应 DOM 或对应接口字段。
   - 行为级：排序、分页、筛选、批量、导出、复制、状态流转、校验、禁用条件、空态/错态。
   - 文案级：mockup 里明确的规则说明（例如「不选等于全部」「宽限期 3 小时」「未交与失败不参与平均分」）
     是否在实现里有等价表达。
3. **接口级**：实现调用的 `/api/...` 在后端是否存在对应 Controller？反过来，mockup 要求的数据
   后端有没有能力给出？（缺接口 → 标 `阻塞: 缺接口`，不要笼统写「未实现」）

## 二、严重度

| 级别 | 含义 |
| :--- | :--- |
| P0 | 页面整体缺失，或核心任务在该页做不完（无法完成该屏的主操作） |
| P1 | 页面上某个明确的功能点缺失（mockup 有控件/能力，实现里找不到对应实现） |
| P2 | 功能在但被简化（少了列、少了筛选项、少了状态、少了批量入口等） |
| P3 | 文案/交互细节偏差（提示语缺失、空态不同、排序默认值不同等） |
| OK | 已对齐，无需改动 |

## 三、证据要求（硬性）

- 每条结论必须给 `文件:行号`（实现侧）或 mockup 行号（`interface.html:NNN`）。
- 说「缺失」之前必须证明找过：至少用 `grep` 在 `web/src` 全目录搜过相关关键词（中文 + 英文 +
  i18n key 三种写法），并把搜索词写进结论里。
- 不确定的写 `待确认`，不要猜成「缺失」。

## 四、输出格式

文件：`docs/reports/mockup-parity/<area>.md`，中文，结构：

```markdown
# <area> 对等性审计

## 0. 汇总
| 屏 | 路由 | 结论 | P0 | P1 | P2 | P3 |
| --- | --- | --- | --- | --- | --- | --- |
（每屏一行；结论取值：对齐 / 部分缺失 / 缺失）

## 1. <screen id> · <中文名>
- 路由与入口：`/xxx`（`web/src/...:NNN`），导航可见性：教师/学生/仅二级页
- 主操作可达性：能 / 不能（原因）
### 功能点对照
| # | mockup 要求（interface.html:NNN） | 实现情况 | 证据 | 级别 |
| --- | --- | --- | --- | --- |
### 差异说明
（只写表格里非 OK 的条目，一条一句，说清「差在哪、影响什么」）

## 2. ...
## N. 本区域阻塞项
| 问题 | 缺的是什么（接口 / 字段 / 组件） | 建议处理 |
```

## 五、禁止事项

- 不许改任何业务代码、不许改 mockup、不许改 spec。只读 + 写自己的报告文件。
- 不许把「没找到」直接写成「缺失」；先搜三种写法（中文、英文、i18n key）。
- 不许把 mockup 里明显是原型占位（二维码占位、示例数据、主题切换条、`.proto` 提示条）
  当成功能缺失；这类只算 P3 备注或直接忽略（在报告里说明忽略原因）。
- 不许重排/美化已有报告文件；只写自己那份。
