## 3. 代价最大的问题（按损失排序）

1. **静默：用户在等，但没有任何可观察信号。** 后段 90 条用户发言里 29 条是纠错/不满，其中 **8 条**是「不出声」；全期最长静默 **207 分钟**（`a9abe667 14:54`「为啥后台一个任务跑了3个多小时了」），品牌视觉会话 70 分钟无文本被催（`46bcc371 16:32`「做到哪一步了哥们」）。
   - 根因不是「模型慢」，是三种东西被感知成同一种：批量工具调用无中间输出、长测试无流式输出、僵尸进程被当成在跑。
   - **关键复发点**：10-19 21:48 用户已定过四行汇报格式，该会话后半段 31 条全部合规；但下一天的会话又回到静默——**会话内口头约定不跨会话**。
   - **为什么写进 AGENTS.md 也没生效**：旧条款写的是「每轮结尾必须输出」。在这个 harness 里，「轮」= 用户发一条消息到 agent 交出控制权；一次 200 步的轮只算一轮，所以这条规则的触发点恰好落在用户已经等了 70 分钟之后。它是**内容要求**，不是**节奏要求**；模型会用「轮末补一份总结」合规，而用户的痛点在中间。再加上没有计数器（模型感觉不到墙钟）和长上下文里指令衰减，「安静地批量干活」成了阻力最小的路径。
2. **「完成」定义太宽：接口通 = 交付完成。** 3 次完成度被质疑，4 次「造得出、找不到入口」（导入考卷藏在向导第 2 步、试卷建好不知道去哪 assign、找不到 profile 入口）。最贵的一句是 `23880576 23:41`「作为一份可运行、可演示、可继续开发的 v2 软件，它已经开发完成」，14 分钟后被打回「你的功能都没实现完整啊」。
3. **解析器一族缺陷重复 5 次。** `___(9)___` 双写、`11. challenging` 误杀、空数≠题数、`______(7)___` 算两个空、`15. 应用文写作示范范文：`——跨 5 场会话、10-21 16:13 → 10-23 10:19。每次都是「换个卷面写法就崩」，每次当新 bug 修，没有把样例沉淀成契约测试。
4. **静默失败。** 超过 80 字符的题名被**静默丢弃**（「所以 14 分只剩 8 分」）；`env.sh` 默认 stub 比 `application.yml` 默认 ai 旧，QA 上悄悄降级成替身引擎；组内校验不通过就整组退回逐题渲染，无提示。用户只看到「合计对不上」。
5. **并行会话互踩（5 处）。** 同一分钟两个会话都在改 `scripts/env.sh`，产生「不是我改的」假归因；一条 WIP 把另一场会话的全量测试打红；决策 006 是代码改完约 20 分钟后才补写的（顺序倒置）。
   - 现场样本：写这份复盘期间（10:33–10:51），另一个会话就停在同一个仓库上改首页/班级着色，工作区从 15 项涨到 20 项未提交，10:51 才提交成 `703fe72`（T371）。并行不是假设，是常态。
6. **记账漂移（文档不是真源）。**
   - `AGENTS.md:3` 仍写「九个模块」，`pom.xml` 是 10 个；README 写 FR 65 / 任务 224 / 决策 001–008，实测 66 / 225 / 001–009。
   - 002 与 006 各有一个 **T341**；T357/T358 有提交、有 PROGRESS 记录，但 `specs/*/tasks.md` 里 0 行。
   - **296 条 AC 一条都没打勾**（`- [x] AC-` = 0），「这条验收过没过」只能翻提交正文。
   - `AGENTS.md` 自带的重复编号自检命令有**假阴性**：多文件 `grep` 会加路径前缀，`uniq -d` 永远比较不到重复（实测 9 条跨 spec 撞号被静默放过）。
7. **提交卫生。** 2 对 patch-id 相同的重复提交（T340、T341 各提交两次）；`T180–T197` 一个提交 10,728 行、`T211–T250` 一个提交 6,828 行；60/114 个提交在 22:00–01:00。
8. **安全小事两件。** 用户两次把 API Key 直接贴进对话（`10-19 21:06`、`23:20`）——Key 不在仓库里（已核对），但留在了本机会话归档里；另有 `find -delete` 误删已提交文档、靠 git 历史救回（`d04cdad`）。

## 4. 三条根因

1. **规则写在了「每轮结尾」，但事故发生在「工具执行中」。** 现有三行汇报只约束轮末输出；一次轮内连跑 200 次工具时，用户看不到任何东西。要约束的是「静默的时长」和「是否有可观察信号」，不是「有没有写总结」。
2. **验证标准是「命令绿了」，不是「用户点得到」。** 286 个测试全绿、守卫全绿，但验收标准一条没勾、入口缺失 4 次、视觉回归靠人眼——**测试通过 ≠ 交付通过**。
3. **知识只活在会话里，不跨会话。** 汇报格式、解析规则、引擎默认值、并行约定，教过一次就随会话结束而消失。这正是要把它们写进仓库文件的理由——`AGENTS.md` 是唯一跨会话的通道。

## 5. 可以直接落地的改进（AGENTS.md 候选，均有反面证据）

### 5.1 汇报与可见性（已按触发条件改写并写入 AGENTS.md）

- **改成触发式，而不是轮末式**：自上一条文字后连续调用 5 次工具、或要跑超过 60 秒的命令、或一个可验证单元刚完成——满足任一条就发三行，不等轮末。
- **长操作先报再跑**：跑之前先发「跑什么、预计多久」，跑完发真实耗时 + 退出码。
- **输出前自检**：自上一条文字以来调了几次工具？≥5 就先发。「轮还没结束」不是理由。
- **僵尸进程当轮清理**：临时服务用完 `kill` 并写一行「已清理」；`job_list` 里 running 超过 10 分钟且无输出，先查再报。

### 5.2 完成度分层

- 任何「完成」必须落三档之一：**接口完成 / 界面入口完成 / 端到端验收完成**；未做浏览器验收照旧写「仅结构校验」。
- 新增页面必须写「从哪个页面、点什么、到哪个 URL」；用户 10 秒找不到 = 未交付。
- 交付附可核对数字（对/错/分、用例数、行数），不写「已改好」。

### 5.3 先讨论、先复现、先定性

- 用户说「先讨论/先别改」：只复现 + 定性 + 方案对比，**代码不动**，等拍板。
- 收到「regression/bug」：先要可复现的输入（URL、记录 id、导入源文件），再翻 `git log`；先排除数据问题（有 1 次为此浪费 70 分钟）。
- 用户判断错时用证据纠正，不照着错误判断改（「标准答案泄露」实为篇目标签 A–D 拼进题干）。

### 5.4 输入契约与解析器

- 外部输入（试卷 md、答案表、富文本）先收 **3 份真实样例**进 `docs/rubrics/fixtures/` 并接入测试，再改解析；每修一个解析缺陷，同步把该样例加进夹具。
- **静默丢弃即缺陷**：截断、丢弃、降级、替身引擎必须回报「第 N 行/N 条，原因」。
- 同一规则只允许一处实现（长度上限、空标记、评分项选择），其余引用同一常量。

### 5.5 视觉决策

- 颜色/布局/观感先出**可点样张或并排对比图**，再问；不写纯文字问卷。

### 5.6 并行会话

- 同一仓库同一时刻只允许一个**写入**会话；确需并行时先约定：谁提交、谁不碰、dirty 怎么标。
- 提交前 `git status` 看别人的 WIP，不替别人提交；测试红先确认不是并行 WIP 污染。

### 5.7 记账

- 「改了主意」→ 先写 `docs/decisions/NNN-*.md`，再改代码。
- commit 必须引用 `tasks.md` 里存在的 T 号；T 号全局唯一（现在 002/006 各一个 T341）。
- 一个可测单元一个提交；不允许 T180–T197 这种 1 万行单体提交。
- 验收标准由「交付当轮」勾选，并写清验的是哪几条 AC。

### 5.8 文档数字与自检

- 计数（测试数、AC 数、模块数、决策范围）由 `scripts/status.sh` 生成或校验，不手抄。
- 修 `AGENTS.md` 自检命令的假阴性：`grep -o ... specs/*/spec.md` 要加 `-h`（或改用脚本），否则跨文件重复编号永远查不出。

### 5.9 安全

- 不把 API Key 贴进对话；用 `.env`/凭据管理。已贴过的立即轮换。
- 不对仓库跑 `find ... -delete` 一类通配删除。

## 7. 不能丢的东西（keep list）

- 「先讨论再动手」「先出图再改」——4 次零返工与「哇，你太伟大了」都是它们换来的。
- 「主动说没验证」——比粉饰太平便宜得多。
- 守卫脚本 + 基线式增量 + 「证明它会红」。
- 决策模板（含「不采纳」）、按任务号命名的证据目录、双环境 QA。
- 交付附可核对数字，而不是形容词。
