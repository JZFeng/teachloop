# 导航着色调研：首页与班级该不该有颜色

日期：2026-10-23　目的：用户提出「首页、班级太素，也搞个 color code」。本文只做比较与候选值，**不改任何代码**；口径以 `specs/006-brand-visual/spec.md` 为准，最终选择由用户在调研问卷里拍板。

## 0. 现在的口径（事实基线）

- 侧栏 7 项：首页、班级、作业、试卷、批改、复核、报表（教师端；学生端 3 项：首页、班级、反馈）。
- 作业/试卷 = Create 蓝、批改/复核 = Assess 青、报表/我的反馈 = Insights 玫红；**首页、班级刻意中性**（`web/src/app/Shell.tsx` 的 `NavItem` 注释、AC-31.2、决策 006 第 51–55 行）。
- 中性的理由写在决策 006：「功能色是模块身份编码，不是装饰；给中性项硬配颜色会造出第五条语义，或提前消费未上线的 Practice 紫」。
- 选中态：整行 `--accent-weak`（`#E8EFFD`）+ 文字 `--accent-text`，图标块变透明（`web/src/styles/app.css:43-52`、样张 `docs/mock/brand-2026-10-22/index.html:122-140`）。
- 约束：Create 的 tint 就是 `--accent-weak`（两者同为 `#E8EFFD`），所以**新配的 tint 必须和 `#E8EFFD` 拉得开**，否则非选中项会像被选中。

## 1. 12 个可比系统：导航到底怎么上色

| # | 系统 | 导航着色做法 | 对我们的含义 |
| :-- | :--- | :--- | :--- |
| 1 | Google Workspace | 产品=颜色：Gmail 红、日历蓝、Drive 黄绿；颜色只标产品身份 | 「一色一身份」是可行模型，前提是身份稳定 |
| 2 | Microsoft 365 | 应用启动器同理，彩块 + 名牌 | 彩色入口块在成熟产品里是常态，不会显得廉价 |
| 3 | Duolingo | 学习路径的节点按单元/技能色相分区 | 颜色承担**分组**而非装饰，扫读性最好 |
| 4 | Asana | 侧栏顶层（Home/My tasks/Inbox）单色；项目块用用户选的颜色 | 「空间」单色、「对象」彩色，分层清楚 |
| 5 | Jira | 项目用字母+颜色的头像块；全局导航单色 | 颜色跟着对象走，不跟导航位走 |
| 6 | Linear | 导航与列表全单色，颜色只留给状态/优先级标签 | 克制样本：色少，状态色才有效 |
| 7 | GitHub | 侧栏单色，唯一的彩色是语言圆点 | 单色导航不妨碍高密度 |
| 8 | Notion | 默认单色图标，页面可自选 emoji/色 | 颜色是用户资产，不是系统语义 |
| 9 | Slack | 频道列表单色，未读用加粗与角标 | 状态不一定要颜色 |
| 10 | Stripe | 导航单色，产品色只出现在内容区卡片 | 导航中性、内容区着色，是 B2B 主流 |
| 11 | Figma | 文件浏览器单色，颜色在画布里 | 工具型产品把颜色让给内容 |
| 12 | Miro | 看板封面与标签彩色，工具导航单色 | 同上 |

> 取证说明：第 1–3、5–12 条是产品级观察（按各自线上界面描述），第 4 条同时被 `docs/research/2026-10-21-design-system.md` 的 At​lassian 一节佐证；本文没有逐张截屏取证，**不当作已验收结论**。

三种模型：

1. **单色克制（Linear / GitHub / Stripe / Figma / Miro / Slack）**——颜色让给内容与状态。前提是产品只有一个主流程，或用户靠位置记忆。
2. **对象着色（Asana / Jira / Notion）**——颜色绑在用户创建的对象上（项目、页面、看板），导航位本身单色。
3. **身份着色（Google Workspace / M365 / Duolingo）**——颜色绑在稳定的功能身份上，数量和含义都不变。

TeachLoop 已经在走第 3 种：Create / Assess / Insights 三个身份、五个导航项。首页与班级不是功能位，是**空间**（聚合页、对象列表），所以候选只有两条路：

- **空间给一个共享的「结构色」**（石板/海军蓝），语义上仍不新增功能位；
- **空间各给一色**（首页=品牌、班级=人群紫/暖琥珀），等于把身份着色从 3 个扩到 5 个，需要现在就把 Practice 的未来颜色一并定掉。

## 2. 候选色值（已按 `scripts/ui/contrast.py` 同式复算）

| 候选 | ink（亮） | tint（亮） | ink×tint | ink×白 | 暗色 ink / tint | 暗色实测 |
| :--- | :--- | :--- | ---: | ---: | :--- | ---: |
| 品牌海军蓝 | `#0E3676` | `#EAF0FA` | 10.34 | 11.62 | `#8FB4FF` / `#16223A` | 7.66 |
| 石板灰蓝 | `#44546F` | `#EEF2F8` | 6.81 | 7.65 | `#A9B8D4` / `#1C2638` | 7.93 |
| 淡紫（Practice 现值） | `#5B3AC4` | `#EAE0FD` | 5.82 | 7.38 | `#A78BFA` / `#1E1A3A` | 5.83 |
| 琥珀（判分部分对的同族） | `#8A5A00` | `#FFF3D6` | 5.37 | 5.93 | `#FFC85C` / `#2A2110` | 10.32 |
| 绿（判分对的同族） | `#17703F` | `#E6F5EC` | 5.44 | 6.13 | `#6EE7A5` / `#0C2A1D` | 10.30 |
| 对照：Create 现值 | `#1957E7` | `#E8EFFD` | 5.11 | — | `#6FB4FF` / `#14233B` | 7.24 |

五组候选全部过 4.5:1，**都不存在对比度问题**；真正的成本在三处：

1. `#EAF0FA`（海军蓝 tint）与 `--accent-weak` `#E8EFFD` 的 ΔE 很小，非选中项会像选中；海军蓝必须把 tint 压灰（如 `#E9EEF6`）才安全。
2. 紫是 Practice 的占位色（决策 006 明确「不借给导航」）；给班级用紫，必须同时决定 Practice 上线后改用什么色。
3. 琥珀/绿与判分三态同族；虽然判分色只出现在批改/复核屏、导航不在同一视区，但两条命名空间一旦互相借色，后面很难收口。

## 3. 建议（不是结论）

- 若优先「不新增语义」：首页与班级共用石板灰蓝 `#44546F / #EEF2F8`，视觉上比灰图标明显，又不与三功能位抢识别；缺点是两项同色，用户仍可能觉得「没分开」。
- 若优先「扫读与身份」：首页=品牌海军蓝（门面=品牌色，和 Create 蓝靠明度区分），班级=淡紫（人/分组）；同时把 Practice 的未来色改成琥珀或新色，并在决策 006 里写清。
- 无论选哪种：选中态要不要跟着各自色走，必须一起定，否则会出现「班级选中变蓝」的割裂。
