# 本地词表可行性研究：Paul Nation 的 word family 表

- 日期：2026-10-23
- 来源目录：`~/Downloads/basewords_130/`（35 个 txt，共 1.5 MB）
- 用途：背单词的 **word family（词族）** 与 **词频** 数据源
- 结论：**可行，而且应当优先本地**。词族与词频本地给，释义/例句/构词文本仍由 AI 异步生成。

## 1. 文件结构

每个文件是一批「词族」，格式统一：

```
HUNGRY 3194          ← 族首词（headword），行首无缩进，后面是 BNC/COCA 频次
	HUNGER 1124      ← 族成员，行首一个 Tab
	HUNGERED 8
	HUNGERS 12
```

- 词全大写；`basewrd35` 里有带变音符的词（`ÉCLAT`、`COMMUNIQUÉ`）。
- 行尾混用 LF 与 **CRLF**，解析器必须两种都吃。
- 文件内**不保证有序**：`basewrd1` 开头是 `HUNGRY / STUFF / THIRST` 三个散条目，之后才是从 `A` 开始的字母序。不能假设「第 n 行 = 第 n 名」。

## 2. 实测规模（2026-10-23 跑出来的数）

| 文件 | 内容 | 词族 | 词形 | 最大频次 |
| :--- | :--- | ---: | ---: | ---: |
| `basewrd1–30` | BNC 频段 1–30（27 段满 1000 族 + 3 段零头） | **28,276** | **80,585** | 2,525,253（A） |
| `basewrd31` | 专有名词（POLYNESIA、SCANDINAVIA…） | 22,087 | 22,837 | 39,591 |
| `basewrd32` | 前缀/词缀（PRE、SUB、ANTI、NON、UN…） | 50 | 217 | 218,897 |
| `basewrd33` | 学科/技术词（LANDFORM、RUNOFF…，频次多为 0） | 3,380 | 6,605 | 9,166 |
| `basewrd34` | 缩写（ICBM、UHF…） | 1,149 | 1,217 | 17,653 |
| `basewrd35` | 法语借词（ÉCLAT、COMMUNIQUÉ…） | 166 | 204 | 468 |

- 去重后唯一词形 **80,579** 个；跨文件重复极少（实测 0–7 个，按频次高者保留）（`basewrd30` 收了 RIZZ、BODACIOUS 这类新词，与前面撞了）。
- **族首行末尾的数 = 整个词族的总频次**（实测 28,276 个族里只有 3 个出现「某成员频次 > 族频次」，属数据噪声）；成员行末尾是**该词形自己的频次**。族首词自身的频次需用「族频次 − 成员合计」推导。
- 「词族数」与「词形数」的比值随频段下降：第一段 1000 族对应 7072 形（7.1 形/族），第 20 段只有 1.8 形/族。低频词几乎没有派生形式，符合预期。

## 3. 这份数据能干什么、不能干什么

| 需求 | 本地表能不能给 | 说明 |
| :--- | :--- | :--- |
| **word family**（同族词展示） | **能** | 族首词 + 成员就在同一个缩进块里，直接可建 `form → family` 索引 |
| **词频**（排序、显示「第 N 千词族」） | **能** | 频次数字 + 所在文件号共同给出频段；比 AI 估的靠谱 |
| **构词分析**（前缀/词根提示） | **部分能** | `basewrd32` 是前缀表，可用于「这个词以 UN-/PRE-/ANTI- 开头」这类提示；完整的词根词缀拆解仍要 AI |
| 释义、中文翻译、词性分义项 | **不能** | 表里一个释义都没有 |
| 例句与翻译 | **不能** | — |
| 音标、英式/美式发音 | **不能** | 要词典或 TTS |
| 单词配图 | **不能** | V2 再说 |

也就是说：**表格里 5 列（单词/释义/来源/状态/下次复习）里，只有「单词」来自本地表；释义与例句仍要生成。**

## 4. 本地索引的工程可行性

- 规模：1–30 段 80,580 个词形。按「词形 → 族 id + 频次 + 频段」建表，估算 **3–5 MB**；gzip 后 < 1 MB。
- 查询：构建时（或启动时）一次性建 `HashMap`，单个词形查找 O(1)，内存占用约 10–15 MB。没有外部依赖、离线可用、结果确定。
- 与 AI 的分工：**本地表命中 → 直接用族与频次；未命中 → 交给 AI 异步生成（并在生成结果里回族）**。这正好复用已经定下的「异步生成 + 幂等」管线（FR-113）。
- 「不还原词形」的规则不受影响：`run` 与 `running` 仍是两条词条，只是详情页能显示它们属于同一族。

## 5. 已知坑

1. **CRLF**：`basewrd18/19/24/25/30/31` 等多份是 CRLF，按 `\n` 切会多出 `\r`。
2. **大小写**：源文件全大写，入库要统一小写，展示时按原文。
3. **变音符**：`ÉCLAT` 这类词，规范化要保留原形并额外建一个去音标索引，否则用户输入 `eclat` 查不到。
4. **跨文件重复**：7 个词形出现在两份文件里，索引要按「先出现的频段」或「频次更高者」定归属，并记下两边。
5. **顺序不可依赖**：文件不是严格按频次或字母排序，不要用行号当排名。
6. **许可**：页面只有站点版权声明，没有明确的开源再分发许可。**已定（用户 2026-10-23 确认）：原始 txt 不进仓库**——现放在 `fixtures-local/wordlists/basewords_130/`（已被 `.gitignore` 挡住），`WORDLIST_DIR` 默认指这里；仓库里只放转换脚本与 `manifest.json`（来源、文件 sha256、族数/形数），需要时由脚本重新生成索引。

## 6. 建议的落法（给 plan 用）

1. `scripts/vocab/build-wordlist-index.py`：读 `WORDLIST_DIR`，产出 `vocab-wordlist.json`（或 TSV）+ `manifest.json`（来源、文件 sha256、族数/形数）。
2. 生成物按需打包进 `teachloop-vocab` 的 `resources`，或导入一张 `vocab_lexicon_*` 表；两者都行，plan 阶段按「是否要运营侧更新词表」决定。
3. 详情页展示：族成员按频次降序、排除当前词、最多 **N 个（默认 8，可配置）**；列表里显示频段标签（如「BNC 第 3 千词族」）。
4. 未命中的词：异步生成时让 AI 一并给族，落库后与本地索引同表。

## 7. 结论

**本地表值得做，而且比「每个词都问 AI」便宜得多**：它回答的是词族与词频这两个**确定性**问题，而 AI 擅长的是释义、例句这类**生成性**内容。两者不冲突，是分工。

唯一需要用户确认的是许可与「原始文件是否入库」；工程上没有任何阻塞。


## 8. 解析与查找算法（2026-10-23 实测）

### 8.1 解析（一次遍历，构建期做）

```
逐文件逐行：
  raw = line.rstrip("\r\n")          # 兼容 CRLF
  若空行 → 跳过
  if line.startswith("\t") → 当前族的成员行：word, freq = 切分后的首尾
  else                      → 新族：head, family_freq = 首尾；开一个新族
每行只取「第一个 token = 词」与「最后一个 token = 频次」，
中间的空白/Tab 一律忽略（源文件里是 Tab 缩进 + 空格分隔）。
```

实测：1.5 MB / 35 个文件，**解析 60 ms**（Python 原型，单线程）。

### 8.2 建索引

| 索引 | 结构 | 用途 |
| :--- | :--- | :--- |
| `form_index` | `dict[str, (family_id, form_freq)]` | 精确查找：词形 → 所属族 |
| `head_index` | `dict[str, family_id]` | 族首页跳转 |
| `families` | `list[{id, head, band, family_freq, members[]}]` | 渲染词族、算频段 |
| `folded_index`（可选） | `dict[str, family_id]`（去变音符） | `eclat` 也能命中 `ÉCLAT` |

- 规模：**80,579 个词形**；建索引 **17 ms**；常驻内存约 **10–15 MB**。
- 注意：族首词的「自身词形频次」源文件没单列，可用 `族频次 − 成员频次合计` 推导；若结果为负（前述 3 个噪声族），展示时只给族频次、不给单形频次。
- 重复词形（同一拼写出现在多个频段）按「频次高者保留」，并记下所有来源。

### 8.3 查找

```
lookup(word):
  key = NFC(word).strip().lower()
  hit = form_index.get(key)
  if hit is None: hit = folded_index.get(fold(key))   # éclat → ÉCLAT
  if hit is None: return MISS → 走 AI 异步生成，生成结果回填索引
  fam = families[hit.family_id]
  return fam.head, fam.band, fam.family_freq, members_sorted_by_freq_desc
```

实测单次查找 **1–4 µs**（Python 原型）；`run` / `running` 都命中同一个第 1 千词族。

### 8.4 为什么不「每次 grep 文件」

- 80,579 个词形分散在 35 个文件里，每次查询要扫 1.5 MB、约 10⁴ 行，IO + 正则开销在毫秒级；
- 而 hash 查找是常数时间、离线、无外部依赖；
- 索引只在词表更新时重建一次（构建期或启动期），查询永远走内存。

### 8.5 复杂度

| 步骤 | 复杂度 | 实测（Python 原型） |
| :--- | :--- | :--- |
| 解析全部文件 | O(总行数) | 60 ms |
| 建索引 | O(词形数) | 17 ms |
| 单次精确查找 | O(1) 期望 | 1–4 µs |
| 内存 | O(词形数) | 10–15 MB |

### 8.6 以后要支持的其他查找（可选）

- **前缀联想**（搜索框输入 `acc` 出 `accommodate`）：有序数组 + 二分，或 trie；80k 词形建 trie 约几十 MB，建议只对前 1 万高频词做。
- **模糊纠错**（拼错一个字母）：编辑距离 / BK-tree，V2 再说，V1 不做。
