# Troubleshooting

错误处理与边界情况。按“现象 → 原因 → 处理”组织。

## 1. 前置检查失败

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| `Submissions` 目录不存在 | 老师还没放作业，或路径写错 | **停止执行**，提示老师确认路径；不要自动创建空目录后继续批改 |
| `Submissions` 为空 | 作业未放入 | **停止执行**，提示老师放入作业文件 |
| `Rubric.md` 缺失 | 未创建评分标准 | **停止执行**。禁止凭常识或对话内容临时编一套标准 |
| `Grading_Prompt.md` 缺失 | 未创建指令文件 | 用 `references/GRADING_PROMPT_TEMPLATE.md` 生成一份，请老师确认后再继续 |
| `reviews/` 不存在 | 尚未创建输出目录 | 可以创建（这是唯一允许自动创建的目录） |
| `reviews/` 中已有上次结果 | 重复运行 | **先询问老师**是覆盖还是换目录；不要静默覆盖 |

## 2. 文件读取问题

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| `.docx` 读取失败 | 文件损坏或非标准 docx | 尝试 `zipfile` 回退解析；仍失败则记为 unreadable 并在报告中列出 |
| `.docx` 完全读不到 | 当前解释器缺 `python-docx` | 运行 `--check-deps` 确认；安装 `python-docx` 或改用 DSH 运行时解释器 |
| `.pdf` 无可用文本层 | 扫描件（整页是图片） | 标记为需要 OCR 或人工阅读。**装了 `pypdf` 也读不出**——`pypdf` 只能提取已存在的文本层。**禁止**根据文件名或页数猜测内容 |
| `.pdf` 解析库缺失 | 当前解释器缺 `pypdf` | 运行 `--check-deps` 确认；安装 `pypdf`，或请老师转换为 txt / docx |
| 视频作业无时长 | `ffprobe` 未安装 | 在报告中标记该作业需人工确认时长；不要估算 |
| 图片作业（`.jpg`/`.png`） | 手写拍照 | 需 OCR 或人工阅读；不要在无法读取时给分 |
| 文件编码乱码 | 非 UTF-8 | 以 `errors="replace"` 读取，若大面积乱码则标记为不可读 |
| `.DS_Store` 等隐藏文件 | macOS 元数据 | 脚本自动跳过；不要当作学生作业 |

**核心原则：无法读取 ≠ 学生没写。** 读不到内容时，绝不能默认给 0 分，
必须标记为 unreadable 并在最终报告中单独列出。

## 3. 评分一致性问题

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| 同一份作业两次运行分数不同 | 判定标准含主观程度词 | 把 rubric 改写为二元判定；检查 prompt 是否留下自由裁量空间 |
| 某位学生的长度判定与其他学生标准不同 | 未事先规定长度政策 | 全班统一使用同一个计数模型，见 `LENGTH_COUNTING_POLICY.md` |
| JZ 式问题：问候语导致超段 | 问候语被算作独立段落 | 默认政策把问候语并入开头段；若老师选择严格计数，则全班一致执行并在 summary 中说明 |
| 边界敏感的篇幅判定 | 不同计数模型结论不同 | `validate_reviews.py` 会输出 `[TEACHER REVIEW]`，交付时必须提示老师确认 |
| `Total Score` 与三项之和不符 | 手工累加错误 | 校验脚本报 error，必须修正后重新校验 |
| review 分数超出最大值 | 分值写错 | 校验脚本报 error |
| 部分分（如 `2/4`） | rubric 非二元 | 校验脚本报 warning；确认老师是否允许部分分，若允许需在 rubric 中写明每档分值 |

## 4. 校验脚本报错后的处理顺序

1. 先修 **error**（结构、算术、覆盖缺口）——这些必须为 0 才能交付。
2. 再审 **warning**（边界敏感、部分分、教学建议条数）——需要老师判断，不一定改。
3. 修完重跑 `validate_reviews.py` 直到 `RESULT: PASS`。
4. **修改单份 review 后必须重算 `class_summary.txt` 的平均分**，否则校验会失败。

## 5. 覆盖缺口

| 现象 | 处理 |
| :--- | :--- |
| 有作业但没有对应 review | 校验脚本报 `no review file for submission`；补生成该份并重算 summary |
| 有 review 但没有对应作业 | 校验脚本报 `has no matching submission`；确认是否文件名写错，或该作业已被删除 |

## 6. 隐私与安全

| 现象 | 处理 |
| :--- | :--- |
| 学生真实姓名出现在文件名 | 可以按文件名记；若需匿名化，改用学号并删除姓名字段 |
| 作业中含个人敏感信息 | 不要在 review 或 summary 中复述；只引用与评分相关的证据 |
| 需要在报告中引用学生原文 | 只引用支撑评分结论的短句，不要整段复制 |
| 老师要求删除或覆盖已有结果 | 先列出将被影响的文件，得到明确确认后再执行 |

## 7. 批量运行中断

| 现象 | 处理 |
| :--- | :--- |
| 中途失败 | 已生成的 review 文件保留；重新运行前先确定是覆盖还是续跑 |
| 单份超时 | 跳过该份并在报告中记录，不要让它卡住整批 |
| 结果不一致需整批重跑 | 改 rubric 或 policy 后**必须整批重跑**，不要只补改个别学生 |

## 8. 交付前最后检查

- [ ] `validate_reviews.py` 输出 `RESULT: PASS`。
- [ ] 每份 review 都包含分数、三项理由、一条优点、一条建议。
- [ ] `class_summary.txt` 的数量、平均分与 review 文件一致。
- [ ] 所有边界敏感长度判定都已提示老师。
- [ ] 无法读取的作业已单独列出，未被静默计 0 分。
- [ ] 报告中未声称任何未实际执行的操作。
