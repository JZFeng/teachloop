## 1. 摘要

一个部署在公网（阿里云）的多用户作业与试卷批改平台。

教师建班级、发邀请码；学生微信登录、补全手机与邮箱后入班。
**考试**：教师先建一份**试卷**（内容，与班级无关），再把它**布置**给一个或多个班，有倒计时、到点自动交卷。
**作业**：教师直接在「新建作业」里写题目要求、总分与评分标准，发给一个或多个班，无倒计时、过截止仍可交（标迟交）。
到达批改启动时点后系统自动派发：**客观题由代码按标准答案判分，主观题由 AI 按 rubric 判分**。
教师复核（通过 / 修改后通过 / 驳回）后发布；学生看自己的完整反馈与班级概览。
全程审计可回溯，另有报表模块供教学分析。

### 1.1 四个概念，三条边界

| 概念 | 是什么 | 不属于谁 |
| :--- | :--- | :--- |
| **试卷**（paper） | 内容：部分、题项、标准答案、评分项、默认时长；**只用于考试** | **不属于任何班级** |
| **考试**（exam） | 一份试卷 + 参与班级（≥1，可多班）+ 时间窗口 + 时长 | 归教师所有 |
| **作业**（assignment） | 自带题目要求 + 总分 + 评分标准 + 参与班级（≥1）+ 截止时间；**不引用试卷** | 归教师所有 |
| **提交**（submission） | 某班某个学生的一次作答 | 挂在对应的考试或作业上 |

**试卷录一次，可以同时给三个班考**——月考就是典型。所以「试卷」与「班级」之间是**多对多，
且带时间与时长**，必须单独一张关联表承载，不能把班级字段塞进试卷。
作业同样可以一次发给多个班，但它的内容写在布置自身上，不产生试卷。

| 形态 | 内容来源 | 结构 | 判分方式 | 有无倒计时 |
| :--- | :--- | :--- | :--- | :--- |
| **考试** | **必须引用试卷** | 客观部分（有标准答案）+ 可选主观部分 | 客观：代码判分；主观：AI 判分 | **有**（到点自动交卷） |
| **作业** | **布置自带**（题目要求 + 总分 + 评分标准） | 单段题目要求 + rubric，无部分、无题项 | AI 按 rubric 判分 | 无（过截止仍可交，标迟交） |

`kind` 由**内容来源决定**，不是用户可选的模式：有试卷 ⟹ `exam`，无试卷 ⟹ `assignment`。
数据库约束 `(kind = 'assignment') = (paper_id IS NULL)` 保证两者不会混（D-14）。

### 1.2 关键设计立场

| 议题 | 立场 |
| :--- | :--- |
| 标准答案 | 是**数据**（题库表），不是代码；换一张试卷只换数据 |
| 匹配规则 | 抽象成**可扩展策略注册表**，新增题型不改判分主流程 |
| AI 的边界 | AI 只判主观部分；**永远看不到标准答案与客观得分** |
| 复核 | 通过 / 修改后通过 / 驳回；改动程度由系统记录，不由老师主观分类 |
| 分数可见性 | 服务端开关控制**他人**分数是否公布；学生自己永远可见 |
| 提交 | 富文本（基础格式）/ 文件 / 视频；不做 OCR |
| 试卷与班级 | **解耦**：试卷不含班级；关联发生在"布置"上，支持一场多班 |
| 计时 | **服务端权威**：剩余时间由服务端算，前端只做显示插值；到点自动交卷 |
| AI 的可信度 | 无 Key / 失败**不出假分**；评分标准是唯一契约；逐项引用原文；AI 只是草稿，老师最终发布 |

## 2. 角色

| 角色 | 能做什么 | 不能做什么 |
| :--- | :--- | :--- |
| **管理员** | 初始化系统（首个管理员、AI 模型）、创建教师邀请码、查用户、停用账号；**只读查看全部班级与作业、复核队列与报表**（D-11） | 代替教师做评分决定；修改他人教学内容 |
| **教师** | 建班、发邀请码、建作业/试卷与标准答案、发起批改、复核、发布、导出、看报表 | 查看非自己班级的数据 |
| **学生** | 凭邀请码入班、富文本/文件/视频提交、线上作答限时考试、发起新 attempt、看自己的反馈、看班级概览 | 看他人作业内容与评语、看未发布草稿、生成邀请码 |

**所有角色首次登录后必须补全手机号与邮箱才能使用系统。**

## 3. 用户故事与验收标准

### US-1 登录与账号资料

- [ ] AC-1.1 未登录访问受保护页面跳转登录页。
- [ ] AC-1.2 微信登录：桌面显示二维码，微信内直接授权。
- [ ] AC-1.3 同一微信身份重复登录复用同一账号。
- [ ] AC-1.4 管理员用邮箱 + 密码登录（独立于微信）。
- [ ] AC-1.5 退出后会话在服务端立即失效；回放旧 cookie 无效。
- [ ] AC-1.6 开发环境可用本地替身登录；生产环境**必须无法启用**。
- [ ] AC-1.7 首次登录后进入资料补全页，**手机号与邮箱必填**；未补全前除补全页与登出外，
      其余接口一律 403 并提示补全。
- [ ] AC-1.8 手机号与邮箱做格式校验与唯一性校验；v1 **不发送短信/邮件验证码**
      （验证能力、多因素认证为后续版本）。
- [ ] AC-1.9 手机号与邮箱仅用于通知与后续身份验证，不在任何学生可见界面展示他人资料。

### US-2 班级与邀请码

- [ ] AC-2.1 教师创建班级，得到邀请码。
- [ ] AC-2.2 学生凭邀请码加入，成为该班学生。
- [ ] AC-2.3 邀请码**有过期时间，服务端控制，缺省 3 天**；过期或停用后加入返回 404。
- [ ] AC-2.4 邀请码可轮换、可提前停用。
- [ ] AC-2.5 一名教师可有多个班；一名学生可加入多个班。
- [ ] AC-2.6 学生只能看到自己所在班级。
- [ ] AC-2.7 学生**不能**生成邀请码或邀请他人；教师不能把邀请码发给自己已入的班。
- [ ] AC-2.8 **邀请码属于班级，不属于作业**：一个班级一个邀请码；作业与试卷都不产生邀请码。
- [ ] AC-2.9 班级可设**加入截止** `join_deadline`（可空 = 不限制）；过了加入截止后凭码加入
      同样返回 404，已在班学生不受影响（D-9）。
- [ ] AC-2.10 班级列表必须展示邀请码的当前状态：**剩余有效期**、**已停用**、**加入截止**
      （无限制时显示「—」），教师可随时轮换或停用（D-9）。

### US-3 账号开通

- [ ] AC-3.1 首次部署从 `/setup` 创建首个管理员（邮箱 + 密码 + 姓名）；创建后该入口自动关闭，
      已存在管理员时返回 409。命令行 `create-admin` 保留为批量/应急入口。
- [ ] AC-3.2 管理员为教师生成教师邀请码，可设过期时间。
- [ ] AC-3.3 已登录用户输入教师邀请码 → 角色升级为教师，邀请码立即作废。
- [ ] AC-3.4 自助注册或凭班级邀请码只能获得学生角色。
- [ ] AC-3.5 任何接口都不能把学生提升为管理员。
- [ ] AC-3.6 管理员可停用账号；停用后其会话立即失效，数据保留。
- [ ] AC-3.7 管理员在「AI 设置」配置 Provider、Base URL、模型、Temperature、API Key；
      保存后重启 app/worker 生效；也可先「测试连接」验证端点与 Key。
- [ ] AC-3.8 API Key 以 AES-GCM 加密存库，任何接口只返回掩码（如 `sk-****1234`）与是否已配置，
      不返回明文；加密密钥来自 `TEACHLOOP_SECURITY_SECRET`。
- [ ] AC-3.9 未配置 AI Key 时，`engine=ai` 不得伪造分数：调用方明确失败，学生端不显示假分。

### US-4 试卷（内容，独立于班级）

> 对应需求：试卷是试卷，班级是班级。三年级 1、2、3 班同时月考，卷子只录一次。

- [ ] AC-4.1 试卷是**独立实体**，不属于任何班级：含 1..N 个**部分**，每部分声明
      `kind`（objective / subjective）、标题、分值；**创建与编辑试卷不需要选班级**。
- [ ] AC-4.2 主观部分才有 rubric 评分项；客观部分只有题项与标准答案。
- [ ] AC-4.3 总分 = 各部分分值之和；不一致时禁止发布。
- [ ] AC-4.4 试卷可设 `default_duration_minutes`（限时考试用；空 = 不限时）。
      它是**默认值**，布置成考试时可覆盖（AC-26.4）。
- [ ] AC-4.5 已发布试卷的内容锁定；修改需显式确认、产生新版本并写审计。
      已经布置出去的考试使用**布置时的快照**（AC-26.6），不受后续修改影响。
- [ ] AC-4.6 判分方式按部分固定：objective 部分永不送 AI，subjective 部分永不送代码判分。
- [ ] AC-4.7 客观题项除标准答案外，还保存**题干与选项**（题干可空，但空的题项不生成解析）。
- [ ] AC-4.8 支持**整卷粘贴拆分**：教师把整卷文字粘进一个框，系统按题号拆出题干、选项与答案，
      教师可逐项修正。
- [ ] AC-4.9 **新建试卷流程分步**：① 基本信息（标题、`default_duration_minutes`）
      ② 内容（导入或手工编排）③ 标准答案校对（仅客观题）④ 评分项（仅主观）⑤ 预览总分与发布。
      每步可保存草稿，中途退出不丢失。**流程中没有「选择班级」这一步**——班级在布置时才选。
- [ ] AC-4.10 内容导入支持 **.docx / .md / .xlsx** 三种格式，也支持手工逐项添加部分。
- [ ] AC-4.11 若导入文档中**题目与答案写在一起**，必须一并抽取并自动配对；
      **不得**要求教师把题目与答案拆成两个文件。
- [ ] AC-4.12 抽到答案的题项标记为「答案已识别」；未找到答案的标记「缺答案」，发布前必须处理。
- [ ] AC-4.13 低置信度的抽取结果必须标出，且所有字段可人工修正后才允许导入。
- [ ] AC-4.14 导入解析必须同时识别**部分与节**结构：按大题干切分部分、按小节标题切分节，

- [ ] AC-4.15 导入必须能吃掉「真实排版」的文档：Markdown 标题/加粗/列表/表格记号先归一化；题干行内并排的选项（`41. A. old  B. famous  C. different  D. fresh`）必须拆成 4 个选项；正文里没有题号的空（七选五、语法填空）按出现顺序自动接续编号，并把第 k 个空标成 `___(题号)___`；主观题部分（写作/作文/应用文/口语）按 AC-4.21 建为写作题项，不再整块跳过。
- [ ] AC-4.16 试卷没有独立「材料/篇章」字段时，材料必须并入其下每道题的题干开头，使单题取出即可作答；识别出的多个「第X部分」按文档结构建部分并逐题带分值（不套用部分默认分值），单部分文档仍导入到用户选中的部分。      题项落到对应部分；校对表按部分分组展示，并给出「N 个部分 M 节」的统计（D-10）。
- [ ] AC-4.17 **答案输入的受支持形态**（用户 2026-10-20 实测三种写法都不能用后确定）：
      ① **答案区**：`答案` / `参考答案` / `标准答案` / `正确答案` / `Answer(s)` 单独成行（冒号可有可无，`【】` 包裹同样认），其后按 `1. A`、`1 A`、`1-5 ABCDA`、`1 A 2 B 3 C` 任一写法逐条给答案；
      ② **纯字母串**：如 `ABCDA`，仅当答案区之前最后 N 道题的题号**连续**时按顺序配对；题号不连续必须拒绝并给出可定位的告警，**不得**猜测配对；
      ③ **行内答案**：题干里的 `（答案：A）`、`(答案: A)`、`【答案：A】`；
      ④ **独立答案表**：校对页粘贴答案表，走 `POST /api/papers/{id}/answers`，与卷面互不影响。
      **明确不支持**、且必须给出可操作提示的形态：无字母的选项（`A comedy film.`）、只有对勾没有字母的标记（`[√] A. …`）、把 `答案：A` 逐题写在题后（答案区只能有一处且必须在卷面之后）。
      **漏填不得让整卷导入失败**：只有题号没写答案（如 `3.`）记为提醒并跳过，该题进入缺答案清单。
- [ ] AC-4.18 判断题（√/×）的答案不走字母通道：标准答案的字母解析只覆盖 A–G，超出范围的形态另立需求，不在此条放宽。
- [ ] AC-4.19 **答案的朴素写法与填空题文本答案**（用户 2026-10-20 用真实卷子验证后确定）：
      ① **逐行怎么写都认**：`1A`、`1.A`、`1 A`、`1、A`、`1）A` 等价；一行多对 `1A 2B 3C` 等价；
      ② **区间答案允许空格分隔**：`1-5 ABBCC` 与 `1-5: A B B C C` 等价（字母个数必须等于题数）；
      ③ **答案表的排版装饰先剥掉**：粘贴内容先过 Markdown 归一化（`---`、`#`、`**`、列表、表格），报错行号仍指原文；
      ④ **填空题的答案是文本**：题项没有选项时，`56. challenging`、`66. to walk  67. impressive` 整行按题号切成文本答案，尾部「空格+左括号」起的说明截掉；**选择题不接受非字母答案**，写错要明确报错，不得静默存成字母；
      ⑤ **答案区容错**：答案区里的小标题、范文、中文解析跳过而不中断；只有**以题号开头却解析不出**的行才报错；整份答案区一条都没解析出来时仍报错；
      ⑥ **答案区标题放宽**：整行含「参考答案 / 标准答案 / 正确答案」之一、长度 ≤40、无句末标点即认定为答案区，使 `试卷参考答案与解析 (卷末附录)` 生效。
- [ ] AC-4.20 **界面文案集中可改**（用户 2026-10-20「很多翻译不准确、我改起来要方便」）：
      ① 前端全部文案集中在 `web/src/locales/zh-CN.json` 与 `en.json` 两个文件，一份语言一个文件，改一句只改那一行；
      ② 两个文件的**键集合必须完全相等**，值不得为空、不得等于键名本身；
      ③ 组件里不得出现用户可见的中文字面量（`web/src/**/*.tsx|ts`，locales 与 i18n.ts 除外），存量用基线锁住、新增即构建失败；
      ④ 后端 `ApiException` 的消息**可以是消息 key**：是 key 就按 `Accept-Language` 解析，是历史中文原文就原样返回（存量行为不变）；
      ⑤ 前端每个 API 请求带 `Accept-Language: <当前界面语言>`，使后端 message 的语言与界面语言一致，而不是跟随浏览器语言。

- [ ] AC-4.21 **写作题建题**（用户 2026-10-22 实测「写作题其实是多个、rubric 只能填 1 个」后确定）：
      ① 标题命中「写作 / 作文 / 应用文 / 书面表达 / 口语 / 演讲」的部分**不再跳过**，按下列粒度建 `ESSAY` 题项；
      ② 部分内有「第X节」→ **一节一题**（如 `第一节 应用文写作`、`第二节 口语表达`）；没有节、但有带题号的写作任务行 → 一行一题（如 `15. 应用文写作（满分 15 分）`）；两者都没有 → 整块 1 题并给提醒；
      ③ **有节时，节内的 `1. 表达理解；` 这类编号行是内容要点，不是新题**，不得拆成多道作文；
      ④ 题号：显式题号优先，没有则取全卷最大题号 +1 顺序递增；
      ⑤ 分值从 `满分 N 分`、`(N points)`、`（N分）`、`N pts` 取；任务行没有取节标题，再没有按「部分满分 ÷ 任务数」均分并提醒；仍为 0 时提醒，发布端按分值 > 0 拦截；
      ⑥ 题干 = 任务标题 + 说明段 + 卷面给出的开头/落款（`Dear Chen Ming,`、`Good morning…`），纯下划线作答行去掉；
      ⑦ 写作部分若已有 `section_criteria`（旧做法），导入时提醒「评分项 N 分与写作题分值重复」，发布时前端拦截，避免总分虚高。
- [ ] AC-4.22 **题面分值语法**（用户 2026-10-22「(5 points)、（5 points）、（5分）都要支持」）：
      ① 题项行、小节标题、写作任务行的分值统一接受 `分 / points / pts`（单复数、大小写不敏感），括号全角半角均可；
      ② `每小题 1.5 分`、`每小题 1.5 points`、`1.5 points each` 三种写法等价；
      ③ rubric 评分项的分值由后端校验器、判分侧、前端预览三处解析，**三处使用同一套 `分|points?|pts?` 规则**，并共用 `docs/rubrics/fixtures/rubric-cases.json` 夹具各测一遍。
- [ ] AC-4.23 **写作参考范文**（D-25）：
      ① 答案区里以**写作题题号**开头的行（如 `15. 应用文写作示范范文：`）是该题参考范文的入口，其后直到下一个写作题号或一条可解析的客观答案行，全部归该题 `reference_markdown`；
      ② 进入范文态后，范文内部以数字开头的行**不再**按「无法解析的答案行」报错；
      ③ 范文没有题号 → 跳过并提醒「写成 `15. …` 可绑定到对应写作题」，**不得**按顺序猜归属；
      ④ 参考范文只存题项、只给教师端（向导第 4 步、复核详情）看，**不进 AI prompt、不进学生端**；
      ⑤ 客观题题号开头却解析不出字母答案的行，仍按 AC-4.19⑤ 报错。

### US-5 标准答案与匹配策略

- [ ] AC-5.1 客观部分可按题号批量录入：题号、分值、**可接受写法数组**、匹配策略。
- [ ] AC-5.2 匹配策略是**可扩展的注册表**（strategy 模式）：内置
      `exact`（完全相同）、`normalized`（忽略大小写/空白/标点）、
      `choice`（单字母单选）、`set`（多选无序）；
      新增策略只需注册，不修改判分主流程。
- [ ] AC-5.3 支持"每题同分"的快捷录入（如 1–20 题各 1.5 分）。
- [ ] AC-5.4 支持整行粘贴导入（如 `A B A C C` 或 `1 A` 每行一条）。
- [ ] AC-5.5 题号在同一部分内唯一；题项分值之和必须等于该部分分值。
- [ ] AC-5.6 标准答案以数据存储，代码中**不得出现任何具体题目或答案的常量**。
- [ ] AC-5.7 每题的**题型** `question_type` 是题目自身的属性，取值四种：
      `single_choice`（单选，选项渲染为单选按钮，只能选一个）、
      `multiple_choice`（多选，选项渲染为复选框，可勾选多个）、
      `fill_blank`（填空，题干内嵌文本框，填词或短语）、
      `essay`（写作，多行文本域，由 AI 评分）。
- [ ] AC-5.8 题型**可以自由设定**：教师可逐题设定或按题号区间批量设定；
      导入时系统按「是否带选项 / 是否带字数要求」给出**默认值**，教师可覆盖。
      同一份试卷、同一部分内四种题型可任意混用。
      渲染与判分都按 `question_type` 派发，**不得按部分名硬编码**——
      「完形填空」的空可以是单选也可以是填空，取决于该题怎么设定。
- [ ] AC-5.9 题型互相转换时不丢已有作答：`single_choice` → `multiple_choice` 保留原选项，
      反向多余选项被截断并标出；`choice` 类 ↔ `fill_blank` 之间不做静默转换，需教师确认。
- [ ] AC-5.10 多选的判分规则可逐题配置：`all_or_nothing`（全部选对才得分，**默认**）
      或 `partial`（选对得分、选错扣分，总分不低于 0）。单选与填空固定为全对才得分。
- [ ] AC-5.11 写作题的字数要求是结构化数据而非散落在题面文字里：
      `word_limit`（数值）、`count_unit`（`word` 按空格切词 / `char` 按字符）、
      `limit_tolerance`（「80 词左右」记为 ±20%）。这三个字段驱动字数提示与输入框尺寸。

### US-6 提交

- [ ] AC-6.1 三种形态：
      `rich_text`（编辑器富文本）、`file`（`.pdf` / `.docx` / `.doc` / `.txt` / `.md`）、
      `video`（`.mp4` / `.mov`）。
- [ ] AC-6.2 富文本允许**基础格式白名单**：粗体、斜体、下划线、有序列表、无序列表、小标题。
      不允许链接、表格、图片、脚本。
- [ ] AC-6.3 服务端对富文本做 **HTML 消毒**（allowlist），并提取纯文本供 AI 使用；
      原文 HTML 保留用于回显。
- [ ] AC-6.4 视频限制：时长 ≤ 6 分钟（360 秒），分辨率 ≤ 1920×1080；
      超出时拒绝并指出**具体哪一项超限**。
- [ ] AC-6.5 单文件上限 100 MB。
- [ ] AC-6.6 若作业有客观部分，学生可按题号填写答案，或一次粘贴整行（如 `A B A C C`）。
      **客观作答只能由学生本人写入**：教师不得代填、代改学生答案；
      教师唯一能改的是**标准答案**，改后整批重算并写审计。
- [ ] AC-6.7 客观作答提交后**立即**判分并返回客观得分与错题清单。
- [ ] AC-6.8 图片与其它扩展名一律拒绝（v1 不做 OCR）。
- [ ] AC-6.9 无法解析的文件标记 `unreadable`，不参与评分。

### US-7 新 attempt

- [ ] AC-7.1 学生在截止前可显式发起新 attempt，保留全部历史。
- [ ] AC-7.2 同一 (作业, 学生) 任一时刻只有一条 `active` 提交。
- [ ] AC-7.3 被判分的是最新一次 attempt；教师可查看历史。
- [ ] AC-7.4 `max_attempts` **默认 3**；达上限后拒绝新 attempt，教师可单独放宽。

### US-8 截止与迟交（作答侧）

> 对应需求：作业是形成性评价，过了截止不该把人锁在门外。宽限期管的是「什么时候开始批改」，
> 不是「什么时候不许交」——这两件事以前混在一起，现在分开。

- [ ] AC-8.1 `due_at` 之后提交标记 `late=true`，**仍然接受**。
- [ ] AC-8.2 迟交记录 `late_by_seconds`；班级汇总里「按时提交率」与迟交份数分开统计。
- [ ] AC-8.3 时间以 UTC 存储，按用户时区显示。
- [ ] AC-8.4 视频时长上限与作业的分钟模式篇幅要求互相独立：前者是硬限制。
- [ ] AC-8.5 `grace_hours`（默认 3）**只决定自动批改的启动时点**——等晚交的人交完再批，
      不是学生的作答截止，也不拒绝任何提交。
- [ ] AC-8.6 教师可对**单份**迟交提交执行「拒收」并填写理由；学生可见拒收状态与理由；
      拒收后若仍有尝试次数，学生可重新提交。
- [ ] AC-8.7 限时考试不走本条（它按 AC-26.5–26.8 的到点自动交卷处理），
      也不设迟交概念——考试只有「在窗口内开始，跑满时长」。

### US-9 自动派发

- [ ] AC-9.1 调度器定期扫描 `kind` 无关：`status=published` 且 `close_at ≤ now` 且未派发的作业。
- [ ] AC-9.2 同一作业重复扫描**不会**产生第二次派发（幂等）。
- [ ] AC-9.3 教师也可手动提前派发。
- [ ] AC-9.4 派发时跳过不可评分提交，并在结果中列出原因。
- [ ] AC-9.5 派发动作写入审计。

### US-10 AI 批改（仅主观部分）

- [ ] AC-10.1 AI 只接收主观部分的评分项、学生正文、客观指标。
- [ ] AC-10.2 AI 请求体**不含**标准答案、客观得分、客观作答明细。
- [ ] AC-10.3 模型输出必须是结构化 JSON 并通过校验（项名、顺序、满分、总分一致）；
      不合格重试 1 次，仍失败则标记失败并保留原始输出，不伪造分数。
- [ ] AC-10.4 最终总分 = 客观得分（代码）+ 主观得分（AI 或教师），三者必须自洽。
- [ ] AC-10.5 批改进度通过**轮询**获取（默认 2 秒间隔）；页面刷新或换设备后进度仍正确。
      （2026-10-18 修订：原为 SSE 实时推送，改为轮询以简化运行形态）
- [ ] AC-10.6 单份超时（默认 180 秒）不影响其余提交。

### US-11 复核与人工判分

老师的模型是：**AI 只是可选草稿；老师可以随时人工判分，并按下最终的 green light（通过 / 发布）。**
AI 不可用、失败或老师想直接判分时，流程不被阻塞。

- [ ] AC-11.1 状态：`pending`（待复核）→ `approved`（原样通过）/ `edited`（修改后通过）/
      `rejected`（弃用并重新批改）。
- [ ] AC-11.2 `approved` 与 `edited` 都视为"已批准"，可发布。
- [ ] AC-11.3 系统**自动记录**改动事实：是否改过分、总分子项前后对比、文本 diff、
      操作者与时间。老师**无需**自己判断"这是小改还是大改"。
- [ ] AC-11.4 客观得分默认不可手改；若教师修改标准答案，必须整批重算并写审计。
- [ ] AC-11.5 未批准的草稿学生不可见。
- [ ] AC-11.6 驳回可填原因；驳回后可重新批改该份。
- [ ] AC-11.7 已发布需先撤回才能修改。
- [ ] AC-11.8 篇幅判定边界敏感的提交在复核界面显式提示；批量通过默认跳过它们
      （服务端按正文现算段数与边界标记，见 AC-27.10）。
- [ ] AC-11.9 **复核工作台**是逐份人工判断的页面：左侧待复核列表（含状态），
      右侧为该作者的正文、客观得分与错题、AI 草稿（**可空**）、三态操作按钮。
      它与「批改总览」的区别：总览看**运行状态**，工作台做**人工判断**。
- [ ] AC-11.10 可从「批改总览」与「作业批改详情」直接跳进复核工作台的对应份。
- [ ] AC-11.11 **人工判分是一等路径**：任何已交卷提交（`QUEUED` / `PENDING` / `RUNNING` /
      `FAILED` / `DONE`）都能进入判分页；没有复核行时按需创建，
      `original_subjective` 为空表示「AI 未参与」。
- [ ] AC-11.12 老师填写主观分与评语 / 优点 / 建议并保存后，即可通过、发布；
      **不要求 AI 先完成**。发布仍是老师显式按下的动作。
- [ ] AC-11.13 **AI 不得覆盖人工结果**：已有教师改分、已决策或已发布时，
      worker 跳过该份（AI 成功与失败两条路径都不覆盖）；人工判分后 submission 置 `DONE`，
      不再被派发队列领取。
- [ ] AC-11.14 判分页显示**客观分、当前主观分、AI 草稿**三个数；
      无 AI 草稿时明确标注「AI 未参与」，不得再显示「未接入」。
- [ ] AC-11.15 批量通过**跳过**「AI 未参与且老师未填分」的复核，避免 0 分误发布；
      同时跳过边界敏感、AI 失败、未通过质量闸门的份（AC-27.13）。
- [ ] AC-11.16 审计记录人工判分的来源（`manual` / `ai`）、改分前后值与操作者。

### US-18 错题解析（题目级共享）

学生看到每道错题的解析。解析以**题目**为单位生成、全作业共享，同一道题只调一次模型。

- [ ] AC-18.1 解析的粒度是**题目**，不是学生：同一作业内同一题只有一份解析，
      多个学生复用（数据库唯一约束保证）。
- [ ] AC-18.2 只对**至少被一人答错**的题生成；无人答错的题不生成、不调用模型。
- [ ] AC-18.3 生成数量上限可配（默认 **50**），按**答错人次降序**选取；
      超出的题不自动生成。上限按班级维度计算，不按学生维度。
- [ ] AC-18.4 超上限的题，教师可对单题**手动触发生成**。
- [ ] AC-18.5 生成时机：主观题 AI 批改全部进入终态后，作为同一流程的下一步执行。
- [ ] AC-18.6 **发布不等待解析**：教师可先复核发布，解析生成后学生侧自动补上。
- [ ] AC-18.7 解析失败不影响分数、不影响发布；失败项可重试。
- [ ] AC-18.8 学生反馈中，每道错题附带该题解析；未生成的显示「解析未生成」，
      **不得显示编造内容**。
- [ ] AC-18.9 解析语言与作业 `feedback_language` 一致。
- [ ] AC-18.10 教师修改标准答案或题干后，该题解析失效并标记为待重新生成。
- [ ] AC-18.11 解析成本与班级人数无关：50 人错同一题只生成 1 次。

### US-19 教师首页（跨班级聚合）

> 对应需求：老师有多个班级，登录后怎么处理。

### US-21 学生考试视图（线上作答）

> 对应需求：学生需要一份能直接在页面上做题的试卷视图，且作答时视线不必来回切换。
> 已确认（2026-10-19）：**试卷本体即表单（inline）**——题干、选项、作答控件在同一个阅读流里，
> 读完题干就地作答，视线不移动。
> 明确**不做**：常驻答题卡侧栏（每题两次视线切换）、只显示题号的答题卡。
> 纸笔考试不走线上答题，走文件提交（US-6）。

- [ ] AC-21.1 进入考试页即进入**专注模式**：隐藏全局导航，只保留试卷本体与试卷目录树。
- [ ] AC-21.2 试卷本体为**单一可滚动区**，按部分顺序渲染：部分标题、题干、选项、分值；
      作答控件**内嵌在题目中**——客观题选项即按钮，完形与语法填空的空格就在该处填/选，
      主观题就在该处写。学生不需要把视线移到别处才有地方作答。
      同一篇共用材料**只渲染一次**：阅读材料一次 + 下面列题目；完形/语法填空的材料一次 +
      逐空控件，不再把材料重复到每道题。材料里的空可以比本卷的题多（整卷只导入了其中几题）：
      仍然只渲染一次，控件只落在属于本卷题目的空位，其余空位保持横线。分组失败时该组回退到
      「每题自带题干」。
- [ ] AC-21.3 左侧为**试卷目录树**：两级（部分 → 题目），每个题目节点显示作答状态
      （已答 / 未答 / 已标记）；点击节点右侧滚动到该题。
- [ ] AC-21.4 **滚动联动**：右侧滚动到某题时，左侧树自动高亮对应节点、展开其父节点，
      并保持该高亮节点在树的可视区内。
- [ ] AC-21.5 窄屏（宽度 < 1024px）时目录树折叠为抽屉，由一个显示进度的按钮唤出。
- [ ] AC-21.6 提交前先做未答检查：弹层按部分分组列出**未作答题号与已标记题号**，
      点任一题号直接跳过去补答（跳转后弹层关闭）。弹层里始终保留「仍然提交」，
      未答不阻止提交。全部答完时不列题号，只做一次提交确认。
      未答的判定：单选/填空无值、多选一个都没勾，都算未答。
- [ ] AC-21.7 支持保存草稿与断点续答；显示最后保存时间。
- [ ] AC-21.8 提交后立即显示客观得分与错题清单；主观部分标记为待批改。
- [ ] AC-21.9 考试进行中不显示答案与解析，避免泄题。
- [ ] AC-21.10 作答控件按每题 `question_type`（见 AC-5.7）渲染，**不是按部分渲染**：
      单选渲染单选按钮、多选渲染复选框、填空渲染题干内文本框、写作渲染多行文本域。
      **完形填空的空既可以是四选一，也可以是直接填词**——取决于建卷时给不给选项，
      不由"完形填空"这个部分名决定。
- [ ] AC-21.11 滚动联动以**段落**为最小锚点单位：完形填空、语法填空的多个空位于同一段文字内，
      无法为每个空提供独立滚动位置。此时点击题号 = 滚动到该段 + 聚焦该空（选择题打开选项弹层，
      填空题聚焦输入框）；右侧滚动时高亮落在**该段段首题号**；当当前题本就处在这一段内时，不改写高亮。
      空控件：选择题显示题号+已选字母，点开 A–D；填空题行内输入；标记放在空控件/弹层里；
      目录树、已答、标记、提交检查仍按原题号工作。
- [ ] AC-21.12 写作文本域的高度**由字数要求算出**，取「刚好写得下 + 20%」，不用固定高度：
      行数 = ⌈`word_limit` × 1.2 ÷ 每行可容纳字数⌉，
      每行可容纳字数按当前容器宽度与字号**实算**（窗口或侧栏宽度变化时重算）；
      结果再与最小 6 行、最大不超过可视区的区间取并。
      验收：`word_limit=80` 的写作题，文本框应能一次显示约 96 词，不出现滚动条。
- [ ] AC-21.13 写作题显示实时字数「已写 N / 要求 80 词」：
      进入容差区间（64–96 词）时提示消失；低于下限仅提示不阻止；超出不阻止提交。
      计数按 `count_unit` 走——英文按空格切词，中文按字符计数。
      题面已给出的开头/结尾是占位而非作答，不计入 N。
- [ ] AC-21.14 作答状态用**四种互相独立的视觉通道**表达，不靠颜色深浅区分（色盲友好）：
      ① 未答 = 空心（虚线边框、浅灰字母徽章、填空为虚线下划线）；
      ② 已答 = **蓝色实心**（实线边、浅蓝底、字母徽章实心白字、填空为实线深色下划线 + 浅蓝底）；
      ③ 当前焦点 = 主题色（只用于当前题 / 当前输入框 / 当前部分标题）；
      ④ 已标记 = 琥珀色。
      已答用蓝色而非黑色：黑色在灰色背景上读作"禁用"而非"完成"，也过于沉重（不是肃穆场景）。
      蓝色**只表示"这题答完了"这一件事**，不得挪作他用；四套主题各自给 `--done` / `--done-bg`
      两个色值，深色主题下自动反向。同一屏内主题色**不得**用于表达"已答"，
      否则 76 题全答完后整屏变色，当前题与标记都会被淹没。
- [ ] AC-21.15 左侧树的两级都有完成状态：
      - 题目级：未答置灰，已答蓝底；
      - **部分级：该部分名下所有题都答完后不再置灰**，并显示 `已答 x/y`；
        未答完时显示 `x/y` 但仍置灰。
      验收：听力第一节 1–5 全答完后，"听力 · 第一节"整行恢复正常字色。
- [ ] AC-21.16 考试入口页（考前须知）先于作答出现：显示试卷标题、时长、题量、总分、
      开始/截止时间与注意事项；点「开始答题」才进入作答并按 AC-26.5 起算。
      `fixed_window` 模式下改为显示「已统一开考，本场在 hh:mm 结束」，不显示起算按钮。
- [ ] AC-21.17 剩余时间常驻顶部并按 AC-26.7 由服务端驱动；**≤5 分钟时转为警示色并保留显示**。
      刷新页面后按服务端剩余时间恢复，不重置、不归零。
- [ ] AC-21.18 归零后（AC-26.8）：作答控件全部禁用、顶部显示「时间到，已自动交卷」，
      不再接受任何输入；未保存的最后一笔以自动保存为准。

### US-27 AI 批改质量与密钥（2026-10-21 用户拍板）

> 对应需求：复核页里的「AI 建议分 7.5、内容要点 4.5/6、语言准确性 3/4」其实是
> `StubGradingEngine` 的 `0.75 × 10`，不是 AI；真实 AI 既没有 Key，也没有任务背景、证据引用、
> 输出校验与失败状态。老师要的是「AI 先写出一份像 `Alejandro_review.txt` 那样的英文 review，
> 老师改一改就能发」，而不是一个固定比例的假分数。
>
> 已确认：**AI 只做草稿，老师最终审核提交**；预填 AI 反馈，30 个学生可以逐份点，也可以批量通过；
> **没有 Key 就引导设置，绝不假分兜底**；Key 永不明文显示；反馈语言跟随学生界面语言；
> 篇幅按「问候语不计段」的班级政策判定。

- [ ] AC-27.1 **首次初始化不强制 Key**：系统还没有管理员时，`/setup` 创建首个管理员即可；
      AI 配置可稍后在教师设置或 `/admin/ai` 完成。若填写了 Key，保存前调用一次 `test` 校验；
      未填不阻断初始化。Key 只存密文，接口只返回掩码（最多末 4 位），
      前端状态、日志、审计、错误信息都不得出现明文。
- [ ] AC-27.2 **教师没有可用 Key 时被明确引导**：教师/管理员登录后，系统按
      「本人 Key → 管理员全局 Key」解析可用 Key；两者都没有时，在教师端显示不可忽略的提示
      「设置 AI Key 后才能使用 AI 批改」并提供直达 `/profile` 的入口。此状态下人工判分、
      发布、学生反馈全部照常可用，**不得**用固定比例替身出分。
- [ ] AC-27.3 **教师设置页可配置任意 OpenAI 兼容端点**：教师/管理员的 `/profile` 提供
      provider ID、显示名称、baseUrl、模型、Key（可空）、测试连接、加载模型与保存；学生端不显示
      这一块。`GET` 只返回 `configured`、掩码、provider/displayName/model/baseUrl，永不返回
      完整 Key；保存后**下一次 AI 调用即生效**，不需要重启（取代 A-10 的「保存后重启生效」）。
      本地模型（Ollama / LM Studio 等）允许空 Key；云端 provider 仍需要 Key。
- [ ] AC-27.4 **一条作业用谁的 Key**：AI 判分优先使用该作业创建者（`offerings.created_by`）的
      Key，没有则回退管理员全局 Key；两者都没有则该份标「AI 未完成：未配置 Key」。审计记录
      `key_source`（`user` / `global`）与创建者，不记录 Key 本身；同一份重批若 Key 变了，
      记录新的 `key_source`。
- [ ] AC-27.5 **任何环境不得把替身当 AI**：生产/测试台默认 `engine=ai`；`stub` 只在
      `dev` / 测试 profile 显式开启，界面标「开发替身，不是 AI 评分」，`ai_calls` 记
      `engine=stub`，学生端不可见。AI 不可用、鉴权失败、超时、输出不合规时，提交标
      `FAILED` 并显示原因，**不产生任何分数**；老师可直接人工判分（D-15）。
- [ ] AC-27.6 **提示词必须带任务背景**：system prompt 至少包含：角色（TESOL / 学科教师，
      第一轮批改）、作业题目要求（`instructions` / `stem`）、完整 rubric（含判定规则与分值）、
      评分政策（只按 rubric、不因是否同意观点加减分、不虚构、引用原文、简明、不重写全文）、
      输出契约，并声明「按 user 消息指定的反馈语言输出」；user prompt 只含客观指标（词数、段数及
      边界标记、时长）、本次反馈语言与正文。学生姓名、学号、submission_id 不进 prompt。
- [ ] AC-27.7 **逐项证据化输出**：每项返回 `name / points / maxPoints / comment`，`comment`
      必须包含至少一处**逐字出现在学生正文中**的引用（忽略大小写与空白）；另返回
      `overall`（1–2 句总评）、`strength`、`suggestion`，全部使用反馈语言。`criteria` 的名称、
      顺序、满分与 rubric 一致，`total` 等于各项之和，且不超过主观题满分。
- [ ] AC-27.8 **输出质量闸门**：comment 为空、不含原文引用、或短于 15 个字符；
      strength/suggestion 为空或只有「很好/继续努力」这类套话 → 判无效，带纠正提示重试 1 次；
      仍无效则整份失败并保留原始输出，不落分、不发布。引用不存在于正文（模型编造）同样判无效。
- [ ] AC-27.9 **二元 rubric 不给中间分**：rubric 写「是：满分 / 否：0 分」时，模型只能给
      `0` 或该满分；写了分档时只能给档位值；不得给 rubric 未定义的中间分。长度项由服务端
      结论决定（见 AC-27.10），模型不得自行改判。
- [ ] AC-27.10 **篇幅由代码按班级政策判定**：服务端用一套全班统一的长度政策计算段数
      （软换行合并、开头问候语并入首段、连续项目符号列表合并为一段），把段数、政策名与
      「边界敏感」标记传给模型；模型在 reason 里写明段数与政策。四种计数模型的 0/2 结论
      不一致时标「边界敏感」，复核页显式提示、批量通过默认跳过（AC-11.8）。
- [ ] AC-27.11 **反馈语言跟随学生界面语言**：AI 生成反馈时取学生在 `users.locale` 的界面语言
      （`zh-CN` / `en`），不用作业的 `feedback_language` 作为首选；学生语言缺失或不在支持列表时
      回退 `offerings.feedback_language`，再回退 `zh-CN`，并记录实际使用语言。输出校验：`en`
      学生不得出现整段中文，`zh-CN` 学生不得出现整段英文；违规视为输出不合规。
- [ ] AC-27.12 **AI 草稿预填复核表单**：打开复核详情时，教师表单预填 AI 的 `overall`（评语）、
      `strength`（优点）、`suggestion`（建议）与主观分，标记「AI 建议，可编辑」；教师可在同一
      表单修改后保存并发布。未保存前不改变 `reviews` 的教师字段；教师字段一旦保存，AI 结果
      不得覆盖（D-15）。
- [ ] AC-27.13 **批量通过有边界与审计**：教师可勾选多份通过；执行前显示将被通过的份数、
      分数范围、将被跳过项（边界敏感、AI 失败、无草稿、未通过质量闸门）；确认后逐份写
      `review:approved` 审计（`bulk=true`），不整体失败。批量通过只改复核结论，**发布仍是
      独立显式动作**；已发布/已决策的份跳过。
- [ ] AC-27.14 **学生只看到教师最终内容**：学生反馈只展示教师最终发布的分数、评语、优点、建议；
      AI 草稿与逐项理由不自动发布。若教师采纳 AI 文本，审计记录来源（`ai` / `manual` / `mixed`），
      学生端不出现模型内部信息。
- [ ] AC-27.15 **可追溯**：`reviews` / `ai_calls` 记录 model、prompt_version、key_source、
      latency、tokens 与原始输出摘要；复核页显示「AI 草稿」、模型、prompt 版本与生成时间。
      AI 失败时显示具体原因（缺 Key / 鉴权失败 / 超时 / 输出不合规），与「AI 未参与」区分。
- [ ] AC-27.16 **默认 rubric 复核结论落地**：当前前后端默认 rubric（两行、无分值、无判定规则）
      判定为不合格，统一替换为课程 `docs/rubrics/Rubric.md` 的 2/4/4 版本（`Required Length` /
      `Clear Position` / `Explanation and Supporting Details`，二元判定）；作业自己的 rubric
      优先，系统 rubric 只在作业未提供时预填并需教师确认。创建页必须显示解析结果与
      「AI 将看到」预览。

- [ ] AC-27.17 **题项级 rubric**（D-24）：`ESSAY` 题项可保存自己的 `rubric_markdown`；
      判分优先用本题 rubric；为空时考试**不再回退试卷级**，直接按 AC-27.20 的默认比例合成（D-29）。
      独立作业仍用 `offerings.rubric_markdown`（布置自带、必填）。
      题项 rubric 的分值只约束本题满分，**不计入试卷总分**；非 `ESSAY` 题传 rubric 一律拒绝。
- [ ] AC-27.18 **逐篇判分**（D-26）：每道有作答的 `ESSAY` 单独一次模型调用，调用次数等于有作答的
      写作题数；逐项评分带题号（`itemNumber`），主观分为各篇之和，评语/优点/建议按「第 N 题（X 分）」
      分段。第 15 题的 rubric 不得出现在第 16 题的 prompt 里。
- [ ] AC-27.19 **作文正文来源与空白**：考试作文正文取自 `answers[]` 中该题号的作答（仅当全卷只有
      1 道 `ESSAY` 且无该行时回退 `contentText`，服务独立作业）；空白作文记 0 分、**不调用模型**、
      不编造评语；任意一篇重试耗尽 → 整份 `FAILED`，不落假分。

- [ ] AC-27.20 **无 rubric 的默认判分（D-28）**：题项级与试卷级 rubric 都为空时，不做均分，
      按配置 `teachloop.grading.essay-default-rubric.content-percent`（默认 80，取值 1–99）合成两项
      rubric：**内容与任务完成**占 X%、**语法与拼写**占 100−X%；两项分值按本题满分拆分且相加等于满分
      （内容四舍五入取整：15 分 → 12 + 3；14 分 → 11 + 3；70% 配置 → 11 + 4）。题目全文（`stem`）必须进 prompt 的「题目要求」。
      设置位置：题项级在向导第 4 步每道写作题（`PUT /items/{n}`）。**试卷级 rubric 已退役**（D-29）：
      界面不再提供，考试判分不再读取；`papers.rubric_markdown` 列与 `PUT /papers/{id}/rubric` 保留兼容，
      仅独立作业仍用布置自带 rubric。反馈语言为 `en` 时
      rubric 文案用英文；非法比例在启动时失败，不静默降级。向导第 4 步把当前比例回显给老师
      （`PaperDetail.essayContentPercent`，只读、不参与保存），让「改了 config」看得见。
      旧版系统伪造的那段「内容要点 / 语言准确性」无分值 rubric，在判分时视为「没有 rubric」，
      同样按本比例合成，存量卷不需要重新布置。老师写了题项级/试卷级 rubric 时永远以
      老师写的为准。

### US-28 评分标准契约与质量基准

> 对应需求：评分标准是 AI 判分的**唯一契约**。当前默认 rubric 没有分值，`RubricCriteria` 会把
> 总分平均分给两项；提示词里也没有判定规则，模型可能给出 rubric 不允许的中间分。质量不能只靠
> 「模型这次表现不错」，要有可复现的基准。

- [ ] AC-28.1 **rubric 优先级**：作业/试卷自带的 `rubricMarkdown` 优先；作业未提供时把系统
      课程 rubric（`docs/rubrics/Rubric.md`）**预填到创建表单并要求教师确认或修改**，
      提示「这是系统默认，建议改成本课标准」；不得用系统 rubric 静默覆盖已有 rubric，
      也不得在教师未确认的情况下直接用于判分。
- [ ] AC-28.2 **录入即校验**：保存作业/试卷时解析评分项名称、满分、判定规则（二元或分档）；
      要求名称非空且不重复、每项有明确分值、各项之和等于作业总分；不满足时阻止保存并指出
      具体项。**禁止**在缺分值的情况下静默平均分配（现有遗留 rubric 标记「需补全」）。
- [ ] AC-28.3 **判定规则必须可执行**：每项至少写清「是/否」或分档边界；只写「内容好」这类
      描述不算可执行规则，保存时给 warning 并列出该项。二元项在提示词与输出校验中都按
      0/满分处理。
- [ ] AC-28.4 **「AI 将看到」预览**：创建页展示实际会进入 system prompt 的 rubric、评分项、
      评分政策与输出契约（只读、可展开）；教师能在保存前发现「AI 看不到我的要求」。
- [ ] AC-28.5 **导入与模板**：支持导入 `.md` 评分标准；提供课程默认模板（2/4/4、二元判定、
      含总分行）与可选的分档模板。导入后同样走 AC-28.2 校验；模板只是起点，必须由教师确认。
- [ ] AC-28.6 **默认 rubric 判定**：现有前后端两份默认 rubric 都缺分值、缺判定规则、缺总分，
      且前后不一致（前端两行标题、后端两句描述），判定为不合格；统一为一份课程默认 rubric，
      前后端读同一来源（接口或 classpath），不再各写一份。
- [ ] AC-28.7 **派发后不可变**：AI 判分使用布置时的 rubric 快照；派发后修改 rubric 不改变
      已派发的判分，要改就新建一场（沿用 AC-26.6 与边缘情况「rubric 在派发后被改」）。
- [ ] AC-28.8 **锚点可选、需授权**：教师可为一条作业添加 0–3 份参考范文（学生正文 + 分数 +
      评语）作为提示词中的 few-shot 锚点；必须匿名化（去姓名/学号/联系方式）并经教师确认，
      默认关闭。未添加时提示词不含锚点；锚点超长或注入失败时降级为无锚点并记录，不影响判分。
- [ ] AC-28.9 **golden set 评估**：用 `docs/rubrics/samples` 的 10 份提交与人工 review 跑评估，
      输出逐项 exact/within-one 一致率、总分平均绝对偏差、契约通过率、原文引用覆盖率、
      反馈语言合规率；边界敏感提交单列，不混入主指标。
- [ ] AC-28.10 **质量闸门**：每次改提示词、换模型、改 rubric 结构或长度政策，必须附评估报告；
      非边界样本逐项 exact ≥ 9/10、总分 MAE ≤ 0.5、契约/引用/语言合规 100% 才允许上线；
      未达标必须写明例外与原因，不得静默发布。
- [ ] AC-28.11 **参考基准更正**：按 AC-27.10 的「问候语不计段」政策，现有人工 review 里
      JZ 的 `Required Length 0/2` 与政策（4 段，在 1–4 内）冲突；以教师拍板为准更正 golden set
      （JZ 2/2、总分 10/10；Mark 仍 0/2、8/10；Maria 2/2、10/10），并同步 `class_summary.txt`。
      旧值保留在 git 历史与一份「known-inconsistency」说明中，不静默覆盖。

### US-45 教师自定义 AI 与批改时机（2026-10-23 用户拍板）

> 对应需求：试卷涉及隐私，多数时候用本地 LLM；本地模型通常没有 API Key。当前代码把
> `deepseek-flash` 当默认、空 Key 直接判「未配置」、作业批改只有全局 02:30 cron，
> 教师无法按自己的作息选择固定时间或截止时间。AI 设置还和学生的个人资料共用一个 `/profile`。

- [ ] AC-45.1 **自定义 provider**：教师可填写 provider ID、显示名称、Base URL、API Key（可空）；
      点「连接并加载模型」调用 `GET {baseUrl}/models`，从列表选择模型，失败时仍可手填模型名。
      `baseUrl` 与 `model` 非空即可保存；本地 provider（ollama / lmstudio / vllm / llama.cpp /
      local）或回环/私有地址允许空 Key，云端 provider 仍需 Key 才算「已配置」。
      Key 只存密文、接口只回掩码；保存后下一次 AI 调用生效。
- [ ] AC-45.2 **角色分栏**：学生打开 `/profile` 只看到账号资料、界面语言与主题；教师额外看到
      「AI 与批改设置」。学生请求 `/api/profile/ai-settings` 与
      `/api/profile/grading-preferences` 均返回 403；不新增 `/teacher/settings` 路由。
- [ ] AC-45.3 **教师级批改时机**：作业的 AI 批改按教师个人偏好执行，作用域是该教师的所有作业；
      模式为 `FIXED_TIME`（默认 02:30 Asia/Shanghai）或 `DUE_DATE`。固定时间可改时刻与时区，
      按教师本地日期每天最多派发一次；`catch_up` 控制错过后是否在启动时补跑。
      `DUE_DATE` 模式过了 `due_at + grace_hours` 后由 60 秒扫描派发，**不再等待峰谷时段**；
      峰谷限制只保留给考试（DeepSeek 成本策略），不写死在所有 provider 上。
- [ ] AC-45.4 **隔离与幂等**：一位教师的偏好不影响另一位教师；同一教师同一本地日期重复扫描
      不重复建 run；考试仍按 `due+grace` 由考试扫描派发，不经过教师偏好。
- [ ] AC-45.5 **入口可达**：从侧栏「资料」或顶栏资料入口进入 `/profile`；教师在同一页看到
      AI 配置、测试连接、保存与批改时机；学生看不到这些区块，也不会因接口 403 报错。

## 5. 非功能需求

| 类别 | 要求 |
| :--- | :--- |
| 性能 | 单班 50 份批量批改可在 2 分钟内完成；编排开销 ≤ 0.05 s/份；进度查询响应 ≤ 200 ms |
| 并发 | 多应用实例 + 多 worker 下行为正确 |
| 可用性 | 单份失败不影响整批；worker 崩溃后工作项可被重新领取；ES 不可用不影响批改 |
| 安全 | 全站 HTTPS、Secure Cookie、限流、上传白名单、富文本消毒、越权 404 |
| 隐私 | 日志无正文；学生数据不接第三方分析 |
| 国际化 | 中英双语；错误码稳定 |
| AI 配置 | API Key 只存 AES-GCM 密文、只回掩码；未配置 Key 时真实判分明确失败，不伪造分数 |
| 可维护 | 可替换边界（认证/AI/存储/PDF）+ 可扩展匹配策略 |
| 模块化 | 出卷、答卷、阅卷、报告、可观测、认证与班级各为独立模块；依赖单向、跨模块只走端口、不跨模块 JOIN |
| 可扩展 | **新增一个业务模块（如背单词 / 间隔重复）只应新增表、路由与导航，阅卷模块改动数必须为 0** |

## 6. 边缘情况

| 情况 | 期望行为 |
| :--- | :--- |
| 未补全手机邮箱 | 除补全页与登出外一律 403 |
| 首次部署还没有管理员 | `/setup` 可创建首个管理员；已有管理员后该接口 409 |
| AI Key 未配置或错误 | 初始化时未填/测试失败不允许完成 setup；教师登录后无可用 Key 时提示去 `/profile` 设置；真实判分失败，不产生假分数 |
| 管理员/教师保存 AI 配置 | 下一次 AI 调用即生效，不再要求重启；接口只回掩码 |
| 教师 Key 无效但全局 Key 可用 | 先按本人 Key 调用；鉴权失败时该份失败并提示，不静默改用全局 Key（避免同一批混用两种口径）；审计记 `key_source` |
| 同一条作业换 Key 重批 | 使用派发时解析到的 Key；`key_source` 变化写审计，不覆盖已有人工分 |
| 作业 rubric 缺分值 | 阻止保存并列出缺少分值的评分项；遗留 rubric 标「需补全」，不静默平均分配 |
| rubric 各项分值之和 ≠ 作业总分 | 阻止保存，提示「评分项合计 X 分，作业总分 Y 分」 |
| rubric 在派发后被改 | 使用布置时的 rubric 快照；已派发判分不改变，要改就新建一场 |
| 开头只有问候语 | 问候语并入首段，不计独立段落；reason 写明「问候语并入首段」 |
| 篇幅边界敏感（四种模型结论不一致） | 复核页标「边界敏感」，批量通过跳过；`reason` 写明所用政策与段数 |
| 学生界面语言不在支持列表 | 回退作业 `feedback_language`，再回退 `zh-CN`，记录实际语言 |
| 模型引用不在正文中 | 判输出不合规，重试 1 次；仍编造则失败，不落分 |
| 模型输出语言与目标语言不符 | 判输出不合规，重试 1 次；仍不符则失败，不落分 |
| 锚点含姓名/学号/联系方式 | 保存时拒绝并指出需匿名化；未确认的锚点不进入提示词 |
| 锚点超长或注入失败 | 降级为无锚点，记录原因，不影响本次判分 |
| 批量通过里混有边界敏感/失败/无草稿 | 只通过合格项，其余列在「跳过」清单并说明原因 |
| 学生反馈里的 AI 文本 | 只出现教师最终发布的内容；AI 逐项理由不自动发布 |
| 邀请码过期 | 返回 404，提示联系教师 |
| 宽限期内提交 | 接受并标 late |
| 超过宽限期提交 | 拒绝；教师可单独延长 |
| 视频超时长/超分辨率 | 拒绝并指出具体超限项 |
| 视频无转写 | 不判内容，标"需人工复核"，不判 0 |
| 富文本含不允许标签 | 消毒后丢弃该标签，保留文本 |
| 富文本含脚本 | 直接丢弃并经日志记录（安全事件） |
| 客观题缺答 | 缺项计 0，整体标注"未作答 N 题" |
| 标准答案多写法 | 任一命中即对 |
| 教师改了标准答案 | 整批重算客观分并写审计 |
| 重复扫描同一作业 | 派发幂等 |
| worker 崩溃 | 重试上限后标 failed 并留证 |
| 模型输出不合规 | 重试 1 次；仍失败标 failed，不伪造分数 |
| 多 worker 下进度不一致 | 进度由数据库聚合得出，任一实例返回相同结果；不依赖内存状态 |
| ES 不可用 | 日志降级为本地文件，报表的日志类指标显示"暂不可用" |
| 缺 PDF 字体 | 启动自检失败，导出 503 |
| 学生访问他人反馈 | 404 |
| 一名学生全卷答错 | 仍按上限只生成 Top N 道解析；其余题显示「解析未生成」，教师可按需生成 |
| 解析在发布之后才生成完 | 学生先看到分数与错题清单，解析到达后自动补上，不阻塞发布 |
| 题干未录入的题项被人答错 | 跳过解析生成并在教师端列出，不调用模型 |

## 9. 本轮已确认的决策

| 编号 | 问题 | 决定 |
| :--- | :--- | :--- |
| D-1 | `publish_scores` 挂在哪一层 | **按作业设置**，默认关 |
| D-2 | 客观题作答怎么进系统 | **纯线上，学生自己填**；不提供代录或机读卡导入 |

| D-5 | 是否隐藏学生自己的分数 | **不隐藏**，学生永远可见自己的具体分 |
| D-6 | 学生「班级概览」怎么落地（2026-10-20 mockup 对等审计） | **独立二级页 + 新接口**，六列（姓名/是否提交/次数/提交时间/状态/分数）；见 AC-13.1–13.7 |
| D-7 | 报表导出做哪一段（2026-10-20） | **先接已实现的 xlsx / pdf 导出**（按布置聚合）与日期区间筛选；AC-17.13 的「勾选学生 × 题目」导出**保留为未完成验收**，是否做由后续单独立项 |
| D-8 | 布置创建后能否改（2026-10-20） | **可改全部字段**（内容除外）；**开考后只能延长** `due_at` / `duration_minutes`；变更写审计并提示影响面 |
| D-9 | 邀请码生命周期（2026-10-20） | **过期 + 停用 + 加入截止全做**；默认 3 天过期，过期/停用/过加入截止后 join 返回 404 |
| D-10 | 导入解析的粒度（2026-10-20） | **部分/节与置信度都产出**；校对表按部分分组并标黄低置信度行 |
| D-11 | 管理员能看到哪些数据（2026-10-20） | **只读查看全部班级与作业、复核与报表**（跨教师）；不做评分决定、不改教学内容 |

| D-12 | 真实试卷的材料与主观题怎么落（2026-10-20） | 系统暂无「材料/篇章」字段，材料**并入其下每道题的题干开头**并把空标成 `___(题号)___`；写作等主观题**不产题项**，落成该部分的评分要点（分值计入总分）；识别出多个「第X部分」时按文档结构新建部分，单部分文档仍用目标部分 |

| D-13 | 非试卷作业的题目与评分标准放在哪（2026-10-20，**已被 D-14 取代**） | 原决定：题目要求就是试卷里的题项（写作题用 `ESSAY` 题型、题干写要求）；评分标准用布置上的 `rubricMarkdown`。该决定要求作业先建试卷，**已废止** |

| D-14 | 作业与考试是否在数据层分开（2026-10-20） | **分开**：作业永远自带内容、不引用试卷；试卷只用于考试。`offerings.paper_id` 可空，约束 `(kind = 'assignment') = (paper_id IS NULL)` 保证不混。作业内容在创建时快照为「1 条 `ESSAY` 题项（stem = 题目要求，points = 总分）+ rubric」，阅卷链路不改。存量作业回填 `paper_id = null, paper_version = 0`（内容在快照里保留）。创建请求不再由用户选择 `kind` |

| D-15 | AI 与老师判分的关系（2026-10-20） | **AI 是可选辅助，人工判分是一等路径**。任何已交卷提交都可人工判分并发布，不要求先跑 AI；AI 完成后只作为草稿展示。已有教师改分 / 已决策 / 已发布时，AI 不得覆盖（worker 跳过并记审计）。复核详情显示客观分、当前主观分、AI 草稿三个数；无 AI 草稿时标注「AI 未参与」 |
