## 3. 复习（间隔重复）

| 编号 | 功能描述 | 来源 |
| :--- | :--- | :--- |
| SRC-C1 | 用户能看到「今日待复习」卡片：按**到期时间**排序，可按卡组筛选，可限制数量。 | 2.2 / 6.5 |
| SRC-C2 | 用户对每张卡提交**四级反馈**：1 忘记 / 2 困难 / 3 良好 / 4 容易。 | 2.2 |
| SRC-C3 | 每次复习都留下一条**日志**（哪张卡、什么评分、什么时候、可选的思考耗时），供后续统计与算法调参。 | 2.2 / 4.3 |
| SRC-C4 | 每张卡对每个用户有独立的学习状态，源文档的状态集合为 `NEW / LEARNING / REVIEW / GRADUATED`。 | 4.3 |
| SRC-C5 | 评分会改变「下次什么时候再出现」：忘记 → 很快重来；困难 → 小幅推后；良好 → 按当前间隔放大；容易 → 推得更远。 | 5.3 |
| SRC-C6 | 评分会微调「这张卡对这个用户有多难」（源文档用 ease factor，下限 1.3、上限 3.0）。 | 5.3 |
| SRC-C7 | 具体公式与参数（`旧间隔 × ease`、`×1.3`、忘后 5 分钟等）属于算法实现，**不在需求层定**；需求层只要求「四级评分产生可预期的不同调度结果」。 | 5.3 |

## 8. 源文档没回答、必须由本项目拍板的问题

这些不是源文档的疏漏，而是它假设的使用场景（个人背单词 App）与 TeachLoop（班级 + 教师 + 作业）不同造成的。规格不能在被问之前自己猜。

| 编号 | 问题 | 为什么必须先定 |
| :--- | :--- | :--- |
| Q1 | **谁用**：只有学生自用？学生自用 + 教师能看本班进度？还是教师能建卡组并布置给学生？ | 决定数据归属、权限、导航（一级导航给谁看）、以及是否要跨模块读班级数据 |
| Q2 | **调度算法**：先做 SM-2（源文档的公式）？先做 FSRS？还是先做「极简固定间隔」把闭环跑通？ | 决定验收标准能不能被第三方判定（算法不同，「下次复习时间」的期望值不同） |
| Q3 | **首期范围**：源文档的「第一阶段 MVP」原样落地？还是先做「卡片 + 卡组 + 导入 + 复习」四件套？ | 决定 spec 的用户故事数量与 mock 的页面数 |
| Q4 | 卡组的「共享」形态：个人私有 / 班级可见 / 教师发布只读模板？ | 与 Q1 耦合；影响表是否要带 `class_id` |
| Q5 | 发音：只存音标文本，还是允许上传/引用音频（涉及对象存储与版权）？ | 影响 mock 与导入字段 |
| Q6 | 「今日待复习」的每日上限与新卡上限（源文档没有） | 决定复习页的核心交互与 AC |
