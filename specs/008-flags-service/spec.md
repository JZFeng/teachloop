# 规格说明 — 实验开关独立服务（008-flags-service）

- 特性编号：`008-flags-service`
- 状态：**草稿（2026-10-24），待用户 review**
- 上游：`docs/research/2026-10-24-experiment-opt-in.md`
- 定位：**独立部署的辅助服务，不属于 TeachLoop 的业务领域**
- 部署：本仓 Maven 多模块之一（`teachloop-flags-service`），独立可执行 jar 与独立镜像
- 相关：`specs/007-role-nav/spec.md`（角色矩阵留在 TeachLoop，本规格不含角色语义）

---

## 1. 摘要

用户 2026-10-24 的判断：beta test（新功能先给部分学生试用）与 TeachLoop 的业务没有直接关系，它是辅助工具，不该长在业务里。

本规格把它做成一个**独立服务**，只做三件事：

1. **发邀请**：给某个主体、某个 flag 生成一次性 token。
2. **记订阅**：主体凭 token 兑换后，记录「这个主体显式开启了哪个 flag」。
3. **查订阅**：给定主体，返回其显式开启的 flag 集合。

它**不认识**「角色」「班级」「菜单」「试卷」这些词。TeachLoop 通过服务间 HTTP 调用它，浏览器永远不直接访问它。

### 1.1 关键设计立场

| 议题 | 立场 | 理由 |
| :--- | :--- | :--- |
| 服务懂不懂业务 | **完全不懂**：入参只有不透明的主体 ID 与 flag key | 懂业务就绑死在 TeachLoop，无法复用给别的项目 |
| 角色默认值 | **不放服务**，由调用方算好后再合并 | 「admin 只看班级和 AI」是业务知识 |
| 邀请 token | 一次性、绑人绑 flag、有有效期 | 用户 2026-10-24 拍板：防转发、可追踪渠道 |
| 故障行为 | 服务不可用时调用方**回落为「无实验」** | 实验是增量能力，失效应回到旧行为 |
| 数据归属 | 服务**自己的数据库**，不读 TeachLoop 的 `users` | 独立部署的前提是数据也独立 |
| 认证 | 服务间共享密钥（Bearer），不暴露公网 | 没有跨域登录问题，也不需要用户态 |

## 2. 边界

| 内容 | 归本服务 | 归 TeachLoop |
| :--- | :--- | :---: |
| 谁 opt-in 了哪个 flag | ✓ | — |
| 邀请 token 的生成、校验、消费 | ✓ | — |
| 渠道标识与使用记录 | ✓ | — |
| flag key 的业务含义 | — | ✓ |
| 角色默认矩阵 | — | ✓ |
| 最终「这个用户能用什么」的合并 | — | ✓ |
| 学生的界面（确认页、资料页开关） | — | ✓ |

## 3. 用户故事

### US-64 作为学生，我点一条链接就加入一个新功能，随时能退出

我收到一条一次性链接，点开后看到这个功能的说明，确认即加入；我在 TeachLoop 资料页能看到自己加入了哪些，并一键关掉。
**验收**：见 AC-64.1–64.7。

### US-65 作为发链接的人，我能知道谁加入了、从哪个渠道

每条邀请绑定一个人和一个功能，谁用过、何时加入、从哪个渠道，都能查。
**验收**：见 AC-65.1–65.3。

### US-66 作为开发者，服务不掺业务，加功能不需要改它

服务只认主体 ID 与 key；新增实验只增加数据，不改服务代码。
**验收**：见 AC-66.1–66.3。

### US-67 作为运维者，它挂了不影响 TeachLoop 正常工作

服务不可达时，TeachLoop 照常运行，实验项回落关闭，用户无感知。
**验收**：见 AC-67.1–67.3。

## 4. 验收标准

#### US-64 opt-in / opt-out

- [ ] AC-64.1 服务独立部署，拥有自己的数据库；除 `subject_id` 外不存储任何 TeachLoop 用户字段（不存邮箱、姓名、角色、班级）；`subject_id` 按不透明字符串处理，服务不做格式校验以外的解释
- [ ] AC-64.2 邀请 token 由 ≥128 bit 随机源生成；数据库只存 SHA-256 哈希，不存明文；token 绑定 `(subject_id, flag_key)`；默认有效期 7 天，可传参覆盖；**首次成功兑换即标记已使用，二次兑换不再写入**
- [ ] AC-64.3 兑换的结果必须可区分：本人 + 未过期 + 未使用 → 200 记录 `OPTED_IN`；非本人 → 403；已过期 → 410；已被使用且该主体已在 `OPTED_IN` → 200（幂等，提示已加入）；已被使用但主体为 `OPTED_OUT` → 409，要求走正常 opt-in 或重新发邀请
- [ ] AC-64.4 opt-out 幂等：重复调用返回 204；`OPTED_OUT` 记录保留，不删除历史
- [ ] AC-64.5 再次 opt-in（有有效邀请）后，状态回到 `OPTED_IN`；服务不删除任何历史行
- [ ] AC-64.6 查询接口 `GET /v1/enrollments?subjectId=` 只返回该主体**显式**开启的 flag，不推断、不默认
- [ ] AC-64.7 所有 `/v1/**` 端点要求服务间密钥；无密钥或错误密钥返回 401，且不泄露 flag 是否存在

#### US-65 渠道追踪

- [ ] AC-65.1 每条邀请记录：生成者标识、生成时间、渠道（自由文本，缺省为空）、被邀主体、flag key
- [ ] AC-65.2 enrollment 记录来源邀请 ID，能回答「这个主体从哪条渠道加入」
- [ ] AC-65.3 审计事件覆盖：邀请生成、兑换成功、兑换失败（分类：非本人 / 过期 / 重复）、opt-out。事件不写明文 token

#### US-66 服务不掺业务

- [ ] AC-66.1 服务代码内不出现「角色」「班级」「菜单」「学生」「教师」等业务概念；只有 `subject`、`flag`、`invite`、`enrollment`
- [ ] AC-66.2 新增一个实验只需要：调用方注册新的 flag key、生成邀请、兑换；**服务代码零改动**
- [ ] AC-66.3 TeachLoop 侧集成面只有一个客户端类（`FeatureClient`）加一个 `/api/features` 合并点；业务模块不直接依赖本服务

#### US-67 故障与运维

- [ ] AC-67.1 提供 `/healthz`，返回自身与数据库连通性
- [ ] AC-67.2 调用方超时（≤200ms）或收到 5xx 时，`/api/features` **仍返回 200**，实验项回落为关闭，角色默认不受影响；不向前端暴露错误
- [ ] AC-67.3 调用方对同一主体的结果缓存 30 秒，缓存期内不重复调用服务；请求量可观测（调用次数、失败次数、p95 延迟）

## 5. 功能需求

| ID | 需求 | 对应故事 |
| :--- | :--- | :--- |
| FR-129 | 邀请生成：`POST /v1/invites`，入参 subjectId / flagKey / channel? / ttlDays?，返回一次性明文 token（仅此一次） | US-64 |
| FR-130 | 兑换：`POST /v1/enroll`，入参 subjectId / token，按 AC-64.3 返回结果 | US-64 |
| FR-131 | 查询：`GET /v1/enrollments?subjectId=`，返回显式开启的 flag 布尔映射 | US-64 |
| FR-132 | 退出：`POST /v1/opt-out`，入参 subjectId / flagKey，幂等 | US-64 |
| FR-133 | 邀请查询：`GET /v1/invites/{id}` 与按 subject 列表，含使用状态与渠道 | US-65 |
| FR-134 | 服务间认证：Bearer 密钥，密钥来自环境变量，不落库 | US-64 |
| FR-135 | 审计事件（生成/兑换/失败/退出） | US-65 |
| FR-136 | TeachLoop 侧 `FeatureClient`：超时、重试一次、失败回落、30 秒缓存 | US-67 |
| FR-137 | TeachLoop 侧 `GET /api/features`：角色默认（`nav.*`，见 007）∪ 模块开关 ∪ 服务返回的实验 key，扁平布尔 | US-67 |

## 6. 非功能约束

- 端点 p95 ≤ 100ms（单机、同网络）；查询走 `(subject_id)` 唯一索引，单次 ≤1 次查询。
- token 明文只在生成响应里出现一次，此后任何接口与日志都不返回。
- 服务不监听公网地址；部署上与 TeachLoop 同网络或同机。
- 不做批量导出、不做统计报表（本期）。

## 7. 部署形态

- 本仓新增 Maven 模块 `teachloop-flags-service`，独立 `main` 类，独立 `Dockerfile`。
- 数据库：与 TeachLoop 同实例不同 schema，或独立实例；**不允许跨库 JOIN**。
- 首次启动 policy：由 `spring.sql.init` 或 Flyway 建两张表（`flags_invite`、`flags_enrollment`）。

## 8. 范围外

- A/B 分流、百分比放量（用户 2026-10-24 明确不是 AB 实验）。
- 管理界面：本期由 TeachLoop 的后端调用生成邀请，服务自身只提供 API。
- 复用给多个租户：本期单租户，`subject_id` 已按不透明设计，将来加租户前缀即可。

## 9. 开放问题

1. 服务间密钥的轮换方式（本期：单个环境变量，不支持轮换）。
2. 邀请 token 的有效期默认 7 天是否合适。
3. 是否需要一个「列出某 flag 全部加入者」的端点（本期只提供按 subject 查，反向查询留到有运营需求时）。
